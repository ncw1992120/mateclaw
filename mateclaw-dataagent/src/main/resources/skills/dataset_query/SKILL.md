# 数据集查询技能

当用户基于数据集进行数据查询或分析时，按照以下工作流程操作。

## 工作流程

### 第一步：发现数据集
调用 `query_dataset(action='list_datasets')` 查看所有可用的数据集。
- 每个数据集包含 id、名称、描述、状态、行数、列数等信息
- 根据用户问题推断最相关的数据集；不确定时询问用户
- 优先选择状态为 `ready` 的数据集

### 第二步：查看数据集结构
调用 `query_dataset(action='get_dataset_schema', datasetId=<id>)` 查看数据集的字段结构。
- 字段已区分为维度(dimension)和度量(measure)两类
- 维度字段：用于分组、筛选，如地区、类别、日期
- 度量字段：用于聚合计算，如销售额、数量、金额
- 记住字段名和分类，后续分析时使用正确的字段

### 第三步：查询数据集数据
调用 `query_dataset(action='query_dataset_data', datasetId=<id>, page=1, size=50)` 查询数据集的数据。
- 默认每页 50 条，可通过 size 参数调整
- 如果数据量较大，可分页查询
- 查询结果会以表格形式展示

### 第四步：解读结果
- 用自然语言总结查询结果的要点
- 如果结果为空，分析可能的原因
- 如果查询结果包含数值列，系统会自动生成 ECharts 图表，无需手动生成图表代码
- **重要：不要使用 write_file 工具生成 HTML 图表文件，系统已内置图表渲染能力**

## 使用场景

数据集查询适用于以下场景：
- 用户明确提到"数据集"或"数据视图"
- 用户需要基于已治理的数据进行分析
- 用户需要查看维度和度量的关系
- 用户需要快速了解某个业务主题的数据概况

## 与 SQL 查询的区别

- **数据集查询**：基于已治理的数据集，字段已分类，数据已同步，适合快速分析
- **SQL 查询**：直接查询原始数据源表，灵活但需要了解表结构

如果用户的问题更适合直接查询原始表（如需要多表关联、复杂计算），建议使用 SQL 查询技能。

## 错误处理

如果查询失败：
1. 仔细阅读错误信息
2. 常见原因：数据集 ID 无效、数据集未同步数据、数据集状态异常
3. 如果数据集状态为 `draft`，提示用户需要先同步数据
4. 如果数据集状态为 `error`，提示用户数据同步出现异常
