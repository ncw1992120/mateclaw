# 洞察仪表盘 Python 数据编排与输出契约设计

**日期：** 2026-09-21  
**状态：** 待用户评审  
**范围：** 洞察 → 仪表盘 → 组件库 → 卡片 → 属性配置 → 编辑 Python 脚本

## 1. 目标

为仪表盘卡片建立一条完整、可解释、可预览的数据编排链路：用户可以读取一个或多个数据集，使用运行时筛选条件，编写跨数据集处理逻辑，并将结果稳定地交给表格、指标卡和图表组件渲染。

本设计一次性覆盖以下能力，不按产品阶段拆分：

- 筛选器模板与运行时筛选值分离；
- 查看数据时自动带出已绑定筛选条件；
- 系统生成 Python 区域可进入高级编辑；
- 数据集 A 的结果可以传给数据集 B；
- Python 返回值统一标准化；
- 输出格式、字段和类型在渲染前校验；
- 预览、错误反馈和正式组件渲染使用同一套执行契约。

## 2. 用户心智模型

用户配置的不是一段孤立脚本，而是一条数据流：

```text
数据集 A → 读取/筛选 → Python 处理 → 数据集 B → 读取/筛选 → 最终结果 → 组件渲染
```

系统自动生成的内容负责展示标准路径；用户扩展内容负责业务逻辑。用户可以修改系统生成区域，但修改后必须明确标记为“用户接管”，系统不能在后续生成时静默覆盖。

## 3. Python 编辑器交互

编辑器包含三个逻辑区域：

### 3.1 系统生成区

默认展示只读代码，内容包括数据集读取、筛选模板和运行时参数：

```python
dataset_a = datasets.read("数据集A")
filters_a = runtime_filters.get("dataset_a", {})
data_a = dataset_a.query(filters=filters_a)
```

提供“高级编辑”入口。用户解锁并修改后：

- 显示“已由用户接管”；
- 保存用户版本和系统版本来源标记；
- 数据集、筛选器或字段映射变化时不覆盖用户代码；
- 提供“查看系统新版本”“对比差异”“恢复系统生成”操作；
- 恢复系统生成必须由用户主动确认。

### 3.2 用户处理区

用于跨数据集读取、Join、聚合、字段计算和结果整理：

```python
orders = datasets.read("订单数据").to_pandas()
customers = datasets.read("客户数据").to_pandas()

result = orders.merge(customers, on="customer_id", how="left")
```

用户代码不得访问数据库凭据、任意网络、文件系统或安装外部依赖。数据集读取必须通过 Runner 提供的 `datasets` 接口。

### 3.3 输出区

输出区展示当前脚本的返回对象类型、标准化结果、字段结构、样例数据和组件预览。用户不需要手工拼接组件私有配置。

## 4. 筛选模板与运行时值

筛选器绑定只定义模板，不携带具体用户值。例如：

```text
metric_time >= ${startDate}
AND metric_time < ${endDate}
```

绑定配置至少包含：

```json
{
  "filterId": "time_filter",
  "inputName": "dataset_a",
  "sourceField": "metric_time",
  "operator": "gte",
  "parameterName": "startDate",
  "required": false
}
```

运行时值在“查看数据”弹窗中产生。弹窗打开时自动带出所有绑定条件，但空值条件不参与查询：

- 只填 `startDate`：执行 `metric_time >= startDate`；
- 只填 `endDate`：执行 `metric_time < endDate`；
- 两个都填：执行完整范围；
- 都不填：不添加该条件；
- 用户可以删除、修改或新增查询条件。

筛选器类型和操作符必须适配字段类型：文本支持等于、不等于、包含、模糊查询、前缀和后缀；数值支持比较和区间；日期支持单点、边界和范围；枚举支持单选、多选和任一匹配；所有类型支持可配置的空值判断。

筛选条件采用结构化表达，不在 Python 或 SQL 中直接拼接用户字符串。执行信息需要显示实际生效条件、已下推条件和未下推条件。

## 5. 跨数据集执行模型

每个组件拥有独立的数据输入白名单和执行上下文。数据集 A 的结果可以作为 Python 内存数据传递给数据集 B：

```python
data_a = datasets.read("数据集A").to_pandas()
ids = data_a["customer_id"].dropna().unique().tolist()

data_b = datasets.read(
    "数据集B",
    filters={"customer_id": {"operator": "in", "value": ids}}
).to_pandas()

result = data_b
```

Runner 必须限制传递值的数量、脚本运行时间、内存和最终结果大小；超过限制时返回明确的资源错误，而不是渲染空结果。执行日志要能显示各输入的行数、输出行数和字段变化。

预览提供三层结果：

1. 单个数据集预览：验证数据源和筛选；
2. Python 处理结果预览：验证跨数据集和用户逻辑；
3. 组件展示预览：验证最终结果经过组件适配后的效果。

## 6. 统一输出契约

Python 可以返回 `pandas.DataFrame`、`list[dict]`、标准结果对象或单值对象，但 Runner 必须在组件渲染前转换成统一结果信封。

### 6.1 表格结果

```json
{
  "schemaVersion": "1.0",
  "kind": "table",
  "data": {
    "columns": [
      {
        "name": "metric_time",
        "title": "时间",
        "dataType": "date",
        "role": "dimension",
        "nullable": true
      },
      {
        "name": "amount",
        "title": "金额",
        "dataType": "number",
        "role": "measure",
        "nullable": false
      }
    ],
    "rows": [
      {"metric_time": "2026-09-21", "amount": 1200}
    ]
  },
  "meta": {
    "rowCount": 1,
    "truncated": false,
    "sourceInputs": ["dataset_a"]
  }
}
```

表格是表格组件、指标组件和图表组件的共同数据基础。图表组件只读取表格字段，再根据组件配置选择维度、指标、聚合和图表类型；Python 不直接返回 ECharts option 或组件私有 JSON。

### 6.2 标量结果

```json
{
  "schemaVersion": "1.0",
  "kind": "scalar",
  "data": {
    "value": 1200,
    "label": "成交金额",
    "dataType": "number",
    "unit": "元"
  }
}
```

### 6.3 消息结果

```json
{
  "schemaVersion": "1.0",
  "kind": "message",
  "data": {
    "level": "info",
    "message": "当前筛选条件下没有数据"
  }
}
```

空表不是错误，应该返回合法的 `table` 结果并显示“暂无数据”。异常、格式错误和资源超限必须使用错误状态，不得伪装成空表或字符串。

## 7. 输出标准化与校验

执行链必须按以下顺序处理：

```text
执行脚本
→ 提取 result
→ 识别返回类型
→ 标准化为 ResultEnvelope
→ 校验 schema/columns/rows/dataType
→ 组件适配
→ 渲染
```

校验至少包括：

- 返回值不是 `None`；无结果时使用合法空表或消息结果；
- 表格必须是二维结构；
- 列名非空且不重复；
- 每行字段可映射到列定义；
- 字段类型一致，日期、数值、布尔和文本可明确识别；
- 不允许将不可识别对象通过 `str()` 静默转成普通文本；
- `NaN`、无穷值和不可序列化值按明确规则转换或拒绝；
- 结果行数、列数和字节大小不超过执行策略；
- `kind` 与当前组件能力匹配。

错误反馈必须指出阶段、路径和修复建议，例如：

```text
脚本执行成功，但输出格式校验失败：
期望：DataFrame 或 list[dict]
实际：字符串
位置：result
建议：返回 result = data 或 result = [{"field": "value"}]
```

## 8. 前端组件适配

组件只消费统一结果，不再自行猜测 Python 原始返回值：

- 表格组件：直接使用 `table.data.columns/rows`；
- 指标卡：使用 `scalar`，或从 `table` 按组件配置聚合；
- 图表组件：使用 `table`，由组件配置声明维度、指标、聚合和排序；
- 无数据：显示空状态；
- 执行或校验错误：显示错误状态和可展开的诊断信息。

预览结果、正式仪表盘查询和保存后刷新必须经过同一个标准化入口，避免“预览能看、正式渲染失败”。

## 9. 兼容与数据安全

- 现有单输入脚本继续可运行；
- 单输入且无 Python 用户逻辑时，直接把输入标准化为表格结果；
- 多输入必须有能产生最终 `result` 的用户逻辑；
- 旧组件 Schema 保持读取兼容，不把旧数据猜测迁移到新组件；
- 系统代码变更不覆盖用户接管代码；
- 凭据、敏感请求头、原始文件内容不进入脚本参数、结果信封或组件 Schema；
- 大结果使用受控结果引用，组件只读取有界预览；
- 每个执行记录绑定工作区、组件和用户权限。

## 10. 验收标准

以下链路必须在一次完整交付中全部通过：

1. 一个绑定时间筛选器的脚本，用户只填开始日期、只填结束日期、两个都填和都不填时结果均正确。
2. 用户查看数据时，绑定筛选条件自动出现在弹窗中，并可修改、删除和新增。
3. 数据集 A 与数据集 B 通过 Python Join 或 `in` 条件组合，三层预览结果一致。
4. 系统生成区可编辑；修改后数据集配置变化不会静默覆盖用户代码，并可查看差异和恢复系统版本。
5. Python 返回 DataFrame、`list[dict]`、标量和空结果时，均能被标准化或得到明确错误。
6. 返回错误结构、重复列、混合字段类型、不可序列化对象、超限结果时，组件显示诊断错误而不是空白。
7. 表格、指标卡和图表均通过统一结果契约渲染；图表不依赖 Python 直接返回组件私有配置。
8. 预览、正式查询、保存刷新使用相同的标准化和校验逻辑。
9. 现有数据集配置、历史仪表盘和已有单输入脚本不回归。
