# 仪表盘预览筛选值贯通数据查询链路设计

**日期：** 2026-09-27
**状态：** 待用户评审
**范围：** 洞察仪表盘预览态中，筛选器运行时值到数据集查询、Python 输入及组件渲染的完整链路

## 1. 目标与验收边界

预览画布中的筛选器值由用户在当前页面实时选择或修改。系统必须使用这份当前运行态值，按筛选器与各数据集输入的绑定关系，逐查询阶段重新查询并渲染所有受影响组件；不能仅使用组件配置默认值、上次查询值或已有结果集快照。

适用组件包括直接数据集绑定及 Python 数据管道输出的 KPI、图表、表格和组合卡片子组件。筛选器既包括维度筛选，也包括时间筛选；筛选范围和绑定关系必须在嵌套组合卡片与页签中保留。

成功链路：

```text
用户当前筛选状态
  → 按筛选器 ID 和目标数据集输入绑定解析参数
  → 各绑定输入分别生成查询计划并读取数据
  → Python 组件消费经过输入查询的 prepared inputs（若配置 Python）
  → Python 输出阶段按其独立配置处理（若绑定）
  → 更新受影响组件数据并渲染
```

无 Python 的组件在输入查询完成后直接渲染数据集结果；未绑定该筛选器的输入不得隐式添加此条件。

## 2. 当前代码事实与问题

预览页 `DashboardPreviewView` 的筛选变更目前触发 `/dashboards/{id}/preview`，并可重跑仪表盘根级 `schema.scriptBindings`。组件级 `datasetPipeline` 结果通过 `restoreResultSetData` 恢复，但筛选变更的刷新调度没有重新执行这条管道。

后端已有 `QueryContext`、`QueryPlanner`、每个输入的 `parameterBindings` 和 `executeComponent` 执行接口。`DashboardExecutionServiceImpl` 仅在组件级执行请求携带 `queryContext` 时构造输入查询计划；当前预览中的根级 `execute` 调用只提交 Python `parameters`，不能替代按输入生成的查询计划。

筛选状态解析器由 `currentPageComponents` 提供组件列表，而该列表当前仅含页面顶层组件。组合卡片嵌套筛选器可能因此失去自身 scope/目标信息。响应刷新还必须区分局部更新与全量替换，避免 scoped 查询只返回部分组件时清除未受影响组件的数据。

## 3. 运行时筛选状态契约

### 3.1 配置与运行态分离

- 筛选器 `defaultValue` 只用于初始化一次预览运行态。
- 用户每次选择、多选、修改日期或清空后，运行态立即更新；后续请求只读取此最新状态。
- 清空值表示移除对应条件，不得回退到 `defaultValue`。空数组、空字符串和 `null` 的无筛选语义必须统一；只有业务明确表示“空集合即无匹配”的参数契约可以触发空结果短路。
- 多选保留用户选中的值数组，不能压成展示标签或丢失其中一项。
- 日期筛选保留筛选器 ID、字段和当前日期范围；后端依据绑定配置解释边界操作符。

### 3.2 标准状态与绑定解析

前端保存当前页面（含组合卡片子树）所有筛选器的运行态，至少可由 `filterComponentId` 唯一定位；每项保存技术字段、当前值、scope/目标关系。每次组件执行前，以组件 ID、输入别名和筛选器 ID 解析绑定，将值映射到绑定配置声明的参数名。参数名、字段名及操作符的权威来源是服务端可校验的绑定配置，不接受客户端自造字段/操作符。

同一个筛选器可绑定多个组件或多个输入，各目标分别映射和校验。未绑定的输入不传该参数；绑定值被清空则不生成该过滤条件。数据集输入查询配置与 Python 最终结果查询配置是不同阶段、不同绑定空间，不得混为一套参数。

## 4. 查询阶段语义

### 4.1 输入数据集阶段

对组件的每一个 `datasetInputs[]`，服务端读取该输入的静态查询配置和 `parameterBindings`，与本次 `QueryContext.parameters` 合并生成独立 `DatasetQueryPlanDTO`。仅匹配当前输入且绑定了当前筛选器的参数形成运行时过滤条件。执行顺序为权限/字段/操作符校验、计划生成、数据源 Adapter 查询、prepared input 物化。

Aloudata 指标与维度输入必须将筛选条件转换为语义层支持的查询参数，并在语义层查询阶段下推；目标契约为 `semantic/api/v1.1/metrics/query`。其他数据源继续通过各自受控 Adapter 执行；不能安全下推时按查询计划的 residual 规则有界处理或明确失败，不得静默忽略绑定条件。

无 Python 时，单输入组件渲染该输入的查询结果；多输入组件需遵循既有明确的组合/Join 契约，不能任选某一个输入或复用过期快照。

### 4.2 Python 处理阶段

存在 Python 脚本时，必须先完成所有输入的查询计划和 prepared input，再启动 Runner。Runner 默认只能按输入别名读取已准备的数据，不负责拼接数据源过滤条件。对某个输入未绑定的筛选器，不得影响该输入；同一个筛选器若分别绑定多个输入，则这些输入各自按其字段/操作符配置处理同一个当前值。

筛选变化必须使所有依赖该运行态筛选器的 Python 组件重新执行；不允许只更新查询弹窗结果而不更新画布，也不允许读回之前 executionId 的旧结果作为新筛选结果。

### 4.3 Python 输出阶段

Python 最终结果集查询配置属于 Python 输出之后的独立阶段。若筛选器在此阶段有绑定，才对 Python 输出做配置的筛选/排序/分页；这些规则不得反向改变已经完成的 Python 输入查询。最后按结果集配置投影字段并用既有 `resultset`/`render` 结果契约更新 KPI、图表、表格等组件。

## 5. 预览协调与刷新行为

筛选变化时，预览运行时根据绑定关系计算受影响组件及其输入，按最新状态创建每组件执行上下文并调度查询。快速连续变化可以防抖合并，但每次执行都必须捕获该次实际值及 `requestId`；只有最新有效请求可提交结果，旧请求晚返回时丢弃。

局部查询响应按组件 ID 合并到现有 `componentDataMap`，不清空未受影响组件。全局筛选只更新全局绑定规则实际影响的目标；组件级筛选仅更新绑定目标。任一输入校验或查询失败时，返回可定位到组件/输入/阶段的错误，不以旧结果伪装为新结果；空结果仍是合法空态。

初次进入预览、筛选器默认值初始化、切换页面、用户改变值、清空值和恢复默认值必须共用同一运行态与调度契约。页面切换仅对新页面可见且有关联的组件执行查询。

## 6. 兼容边界

- 继续读取旧版直接 `dataSource` 与仪表盘根级 `scriptBindings` Schema；旧结构通过适配器转换成相同的运行时筛选语义，不要求一次性迁移保存数据。
- 新组件级 `datasetPipeline` 以 `datasetInputs[].queryConfig` 为输入查询权威配置，执行时使用现有 `executeComponent` + `QueryContext` + `QueryPlanner` 链路。
- JDBC SQL、Aloudata 指标查询及其他数据源必须明确各自支持的绑定和下推能力。静态 SQL 不能因为收到了筛选值就声称已过滤；绑定不可执行时需返回明确提示。
- `finalResultQueryConfig` 仅负责 Python 输出阶段，不得被当成数据源输入过滤配置。

## 7. 验收标准

1. 用户更改维度筛选值后，实际网络请求使用新值；数据集未绑定此筛选器时其查询计划不包含该过滤。
2. 用户更改时间筛选器为 2026-09-01 至 2026-09-02，绑定的 Aloudata 输入请求携带该范围并在语义层查询阶段过滤；Python 收到的是该输入查询后的行集。
3. Python 输入 A 绑定时间筛选器、输入 B 未绑定时，只有 A 的查询计划有日期条件；两个输入都绑定但字段映射不同，则分别按各自绑定查询。
4. Python 最终结果绑定该筛选器时，只过滤 Python 输出阶段；未绑定时不再追加输出过滤。
5. 无 Python 的绑定组件以数据集实际查询结果直接渲染；表格、图表、KPI均更新到同一筛选快照。
6. 单选、多选、切换值、清空值均使用实际运行态；清空后不回退默认值。
7. 组合卡片及页签内筛选器的 scope、绑定目标均保留；筛选只影响其绑定的组件/输入。
8. 多个快速筛选请求乱序返回时，仅最新请求能更新画布；局部响应不清除无关组件数据。
9. 输入查询错误和空结果分别表现为明确错误态与正常空态；旧结果不能被呈现为当前筛选结果。
10. 内部浏览器验证真实预览：至少覆盖 Aloudata 日期筛选、Python 输入绑定/未绑定、无 Python 渲染、清空值、组合卡片 scoped 过滤及连续快速修改。
