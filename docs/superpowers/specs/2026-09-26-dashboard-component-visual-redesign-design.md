# 洞察仪表盘组件库与画布视觉改造设计

## 目标

将洞察仪表盘编辑器从“图标菜单 + 多重边框卡片”提升为统一、克制、有辨识度的专业分析工作台：左侧组件库像轻量组件展厅，便于用户快速辨认和拖入；画布以数据可读性为先，通过主题色、表面层级和组件类型细节建立清晰秩序。

本次只改视觉呈现和组件库浏览体验，不改变数据查询、组件业务行为或仪表盘数据契约。

## 设计原则

1. **内容优先**：数据与图表优先于装饰，画布不能看起来像营销落地页。
2. **同一套语言**：基础组件、图表、AI 卡片和组合容器共享圆角、边框、标题、间距和动效规则。
3. **颜色克制**：主题基础色负责品牌识别，少量主题辅色用于组件区分；红绿仅承载业务状态语义。
4. **层级靠表面，不靠套框**：通过背景深浅、标题区和轻分隔线表现容器层次，避免相邻层级同时加粗边框。
5. **主题可继承**：浅色、暖色和深色主题均从现有 Dashboard Theme Token 派生，不为单个组件硬编码颜色。
6. **操作反馈不抢内容**：拖拽、悬停、选中和缩放状态清晰，但不旋转、不持续发光、不明显缩放。

## 当前实现依据

- `ComponentPalette.vue` 当前按基础组件、常用图表、高级图表分组，物料以纵向“单色图标 + 名称”呈现。
- `InsightDashboardEditorView.vue` 的组件库栏当前固定为 200px；窄屏会变为图标栏或抽屉。
- `DashboardCanvas.vue` 已有统一组件外壳、标题栏、选中/悬停状态及主题强调条。
- `dashboard-theme.ts` 已定义主题表面、边框、文本、强调色、组件层级和组件强调色分组 Token；组件已有 `themeAccentGroup`、`componentColor` 等视觉配置。
- 组合容器会为内部子组件继续提供主题层次样式。

因此本次应扩展现有设计系统和共享组件，不新建一套与其平行的主题机制。

## 方案一：组件库轻展厅

### 布局

- 桌面默认宽度为 **248px**，可拖动调整，范围 **200–320px**；保留现有折叠能力。
- 使用 CSS Grid 自适应：组件库宽度达到 240px 时为两列预览卡；低于 240px 时切换为单列紧凑行，缩略图在左、组件名在右。不得出现名称挤压或横向滚动。
- 组件库顶部、分组标题、组件数量和折叠操作沿用现有结构；继续使用“基础组件 / 常用图表 / 高级图表”分组。
- 窄屏图标栏和移动抽屉维持当前行为；移动抽屉使用单列物料布局。

### 物料卡片

- 两列模式下，每张物料卡以 **约 108 × 88px** 为基准；上部为静态缩略预览，下部为 12–13px 组件名，名称最多两行。
- 单列模式下使用约 56–64px 高的紧凑行，左侧为约 56 × 40px 的静态缩略预览，右侧为 12–13px 组件名；不把窄面板中的行拉成大块空白卡片。
- 预览统一线条粗细、圆角、留白和主题色规则；不使用真实数据、查询接口或 ECharts 实例。
- 不同组件预览必须有语义区别：
  - KPI：数值、指标名称和趋势符号。
  - 表格：表头及少量行列轮廓。
  - 筛选器 / 时间筛选：控件轮廓和简短字段提示。
  - AI 分析：标题、文本线和单个 AI 标识。
  - 组合卡片：容器及内部子卡布局。
  - 图表：按图表类型呈现静态形态，常见图表一眼可区分；高级图表仍沿用现有分组折叠。
- 预览图形和图标消费仪表盘主题 Token。默认状态不为每项增加独立描边；卡片使用轻微表面差异和留白建立分组。

### 交互状态

- 默认：中性表面、清楚名称、缩略预览完整可见。
- 悬停：轻微主题底色、细边框或柔和阴影、`translateY(-1px)`；不旋转、不持续动画。
- 拖拽：显示明确的拖拽光标和拖拽反馈；不缩放原布局，也不改变物料数据结构。
- 键盘：保留 Tab 焦点环以及 Enter / Space 添加组件。
- `prefers-reduced-motion: reduce` 下移除非必要过渡。

## 方案二：画布主题层次与组件外观

### 页面与容器层级

1. **画布底层**：安静、低对比的主题背景，不添加装饰图案或光球。
2. **顶层组件**：卡片表面、单层轻边框、统一圆角和柔和阴影。
3. **组件标题区**：与内容共用卡片外框；只用浅主题色面或一条细分隔线区分，不另起一个有完整边框的小卡片。
4. **组合容器**：容器表面与画布底层有区分；内部子组件使用更轻一层的表面，不重复叠加明显阴影与粗边框。

### 标题、图标和页签

- 组件标题图标统一约 18px，标题间距 6–8px；文字基线、标题字重和编辑态图标位置保持一致。
- 默认图标颜色取当前主题色系的深色阶；图标不使用 Emoji 或随机色。
- 普通标题区使用中性表面，重点组件只允许在标题图标、细强调线或小面积底色体现主题色。
- 组件页签与组合卡片页签共享字体、间距和选中态；选中态以主题色文字/细下划线为主，避免实心高饱和色块占据整个页签。

### 组件差异化

- **KPI**：数值为视觉锚点，名称、单位、趋势形成稳定层级；背景装饰不盖过数字。
- **图表**：标题区轻，绘图区优先；坐标、图例与数据系列保持对比度，不加玻璃模糊层。
- **表格**：卡片外壳保持统一，表头轻主题底色，行分隔与悬停清晰，不给每行增加卡片边框。
- **筛选器 / 时间筛选**：保持控件语义和焦点状态；默认中性，聚焦才使用主题强调色。
- **AI 分析**：允许比普通图表多一点辨识度，例如标题图标或局部柔和渐变；分析正文仍使用高对比的稳定底色。
- **组合卡片**：强调容纳关系，通过容器表面和子卡表面层次表达，不将每一层都框起来。

### 同行组件强调色

- 同一行的数据类组件使用主题色系内的不同强调色组，最多使用主色、辅色和高亮色三组；色彩应低饱和、同一主题协调。
- 优先复用现有 `themeAccentGroup` 和主题色组，不新增任意 HEX 颜色字段或另一套主题配置。
- 组件新增或布局变更后，同一行的强调组分配应确定性；颜色在拖拽过程中不闪动，布局提交后再稳定呈现。保留用户已有显式组件色配置的优先级。
- 正/负向、成功/警告等业务状态色与组件装饰色分离，不能被同行配色覆盖。

## 主题与视觉约束

- 新样式只消费现有 `--db-*`、`--insight-*` 和组件视觉 Token；若确需新 Token，集中定义在主题解析层，不能在各 Widget 中散落常量。
- 暖色主题用于少量强调、图标和局部标题底色，不把卡片主体染成大面积橙/红/黄。
- 深色主题通过足够的表面亮度差、边框和文字对比区分层级；不能仅靠色相区分。
- 正文对比度目标至少 4.5:1；图标和控件边界满足可辨识要求。错误、成功、警告状态同时有文字或图标语义，不只依赖颜色。
- 全局动画控制在 150–250ms；画布中同一视图只保留必要的交互反馈，不加背景漂浮、扫描线或自动数值动画。

## 范围与兼容性

### 包含

- 组件库物料预览布局与卡片视觉。
- 桌面组件库栏宽度调整及窄屏布局适配。
- 画布共用外壳、标题区、页签、组件表面层级与主题色组表现。
- 组合容器内部层级与所有正式 Widget 的一致性。
- 现有主题预设、深色主题、组件标题图标样式和用户显式组件配色的兼容。

### 不包含

- 数据集、查询、事件联动、图表配置和组件业务能力变更。
- 更换 Vue、Element Plus、ECharts 或引入新的 UI 组件库。
- 从 Uiverse/Galaxy 直接拷贝完整组件实现；只允许借鉴轻量渐变、柔和层次和微交互思想。
- 为单个组件新增任意颜色编辑器或新的持久化 Schema 字段。
- 调整仪表盘网格布局算法或用户已经保存的组件坐标。

## 验收标准

### 组件库

- 在 200px、248px、320px 栏宽下，紧凑行/两列卡片切换正确，无横向溢出、名称裁切或预览挤压。
- 基础组件、控件、AI、容器及常用/高级图表均有可辨识的静态预览；没有加载真实查询或创建 ECharts 实例。
- 物料分组折叠、拖拽添加、键盘添加和窄屏抽屉行为不回归。
- 视觉上不像连续堆叠的按钮列表，也不因卡片数量过多变成厚重的卡片墙。

### 画布

- 组件外壳、标题区、页签与组合容器层级统一；主要边界清晰但没有重复框线。
- KPI/图表/表格/筛选/AI/组合卡片仍保留各自信息特点，数据可读性优先。
- 同行主题强调色区分适度且确定；状态语义色、显式用户配色和深色主题不被破坏。
- 编辑选中、悬停、拖拽和缩放状态清晰，不影响已有命中区域与编辑操作。
- 标题图标配置即时作用于画布并在保存、重新打开后保持；组件标题和页签显示正确。

### 自动化和视觉验证

- 单元测试覆盖物料预览类型、响应式列数、键盘行为、拖拽载荷与主题 Token 映射。
- 组件测试覆盖普通 Widget、组合容器中的子 Widget、标题/页签和选中态。
- 运行前端相关测试、类型检查、生产构建和 `git diff --check`。
- 使用 CDP 9222 在真实 Chrome 编辑器检查：默认浅色、暖色主题、深色主题；组件库窄/宽状态；组件外壳、组合容器嵌套、选中态和拖拽状态。记录实际截图并核验没有文字裁切、过度边框或主题对比问题。
- 自动化通过不等于视觉验收通过；若浏览器或服务不可用，视觉项标记为 `BLOCKED`，不以构建结果代替。

## 后续实施建议

这是视觉系统级改造，实施时应先抽出/统一物料预览和共享画布表面规则，再迁移各 Widget 样式，并以组合容器、主题切换和编辑态做集成回归。实现计划需列明具体源码文件、测试文件、运行命令和 CDP 验收步骤；该设计规格获用户审阅通过后再编写实施计划。
