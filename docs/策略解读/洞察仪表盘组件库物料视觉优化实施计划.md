# 洞察仪表盘组件库物料视觉优化实施计划

> **执行约束：** 产品目标仍限定为改善“洞察 → 仪表盘 → 编辑 → 组件库”中可拖拽物料项的外观，不改变该物料功能、画布展示及其他页面。实施期间为通过计划要求的全量测试，按用户“有问题就修问题，直到所有任务完成”的指示，额外修复了全量测试暴露的少量既有前端缺陷，并更新了已过期的布局断言；这些修复与视觉目标无关，单独列明且不扩展视觉改造范围。按任务逐项勾选；每项完成后更新本计划进度。

**目标：** 在保留现有纵向物料列表、分组、拖拽、键盘添加和组件数据契约的前提下，让组件库物料更精致、易辨认、与 MateClaw 当前仪表盘主题协调，同时不形成堆叠的卡片墙。

**实现方式：** 视觉改造限定在 `ComponentPalette.vue` 的局部样式；默认物料项保持轻量列表行，不使用整行常驻描边、卡片渐变、阴影和光效叠加。适度增强图标可见性：图标本体使用主题强调色，以现有主题 Token 派生的低饱和底座承托；Hover 只提供单一轻量背景反馈，键盘焦点保持明确。物料数据、事件、拖拽载荷、分组和画布渲染保持不变。

**技术栈：** Vue 3、TypeScript、Scoped CSS、Vitest、Vue Test Utils、MateClaw 现有 Dashboard Token、Codex 内部浏览器；Chrome CDP `9222` 作为可用时的补充视觉证据。

**适用基线：** 当前 `feature/dev_fu` 分支中的 `ComponentPalette.vue`、其单元测试、`mateclaw-dataagent-ui` 的测试与构建脚本。实施前仍需在目标工作区复核分支、HEAD、脏改动及文件实际状态；本计划不授权切分支、覆盖或清理现有改动。

## 1. 设计判断与视觉目标

当前组件库采用单列纵向列表：SVG 图标与组件名并排，默认图标容器约 18px。它的主要问题是视觉识别度偏弱，而不是缺少复杂动效。组件库承载大量可拖拽物料，必须优先保证密度、扫描速度和拖拽目标清晰。

本轮视觉比例建议：

- **专业与清晰为主：** 中性表面、清楚文字、稳定间距。
- **主题色作少量识别：** 只用于图标及其轻底色、聚焦状态；不使用彩虹配色或随机组件色。
- **动效只表达状态：** Hover 和 Focus 即时可辨，不做常驻发光、扫光、浮动、旋转或缩放。

期望观感：从“纯图标菜单”提升为“精致的分析组件工具栏”，而不是缩小版仪表盘或一列迷你卡片。

### 1.1 建议的物料行视觉

```text
默认：  [柔和主题色图标底]  折线图
悬停：  [柔和主题色图标底]  折线图    （整行浅底色反馈）
键盘：  [明确可见的 Focus Ring]         （无鼠标也能辨认焦点）
拖拽：  保持浏览器现有拖拽图像与命中区域
```

- 维持现有单列列表及相同组件顺序，不扩大面板、不新增搜索或分类 Tab。
- 图标底座建议约 24–26px，SVG 图形保持约 16–18px；底座为约 6px 圆角方形（延续面板既有 `--radius-sm` 方角语系，不用圆形以免偏移动端气质）；避免把 34px 图标容器套进窄侧栏而明显降低列表密度。
- 行高尽量维持在现有约 34px 基线上，建议控制在 36–40px 范围；不得因新增装饰使长列表可见物料数量明显减少。
- 若当前组件库在触控设备上可操作，触控指针下的物料行点击目标至少 44px 高；桌面紧凑密度不因此整体扩高。
- 默认行不使用完整卡片边框、渐变表面、外阴影或独立顶部高光线。整行默认应继续融入组件库面板。
- 图标本体颜色使用 `--db-accent`，底座用 `color-mix(in srgb, var(--db-accent) 8%, transparent)` 派生（与本文件折叠按钮 hover 的 8% 先例一致）；不新增硬编码色值，不将成功/警告/涨跌语义色用于装饰。若深色主题下 8% 过弱导致底座不可辨，可在同一 Token 派生框架内微调透明度，不改 Token 本身。
- Hover 只采用一种主要反馈：使用 `--db-hover` 或由主题 Accent 派生的浅底色，并移除现有 hover 规则中的 `border-color` 变化（现状为底色+边框双反馈）。默认不同时叠加上浮、光晕、边框变色和高光线。
- Focus 使用可见且有足够对比度的焦点样式；不依赖 Hover，也不移除浏览器键盘焦点提示。
- 普通文字对比度按至少 4.5:1 验收；主题色图标底座不能降低名称文字对比度。

### 1.2 明确不采用的方向

- 每个物料项都变成带边框、渐变、阴影的完整小卡片。
- 图标容器 34px 以上并显著增加列表行高。
- 卡片级玻璃模糊、持续 Glow、动态光球、扫光、粒子、旋转、缩放。
- Mini ECharts、迷你 Canvas、远程图片或运行时预览服务。
- 同一行物料各自使用不同颜色；主题色只做统一识别，不能变成彩色菜单。

### 2.3 “不改功能”的可验证定义

视觉改动完成后，以下内容与基线一致：

1. 物料总数、类型、分组及顺序不变（当前源代码基线为基础组件 6 项、常用图表 5 项、高级图表 17 项，共 28 项）。
2. 每个物料仍可拖拽；dragstart 的 `effectAllowed` 仍为 `copy`，`application/json` 数据仍是原 `PaletteItem` 序列化结果，不添加视觉配置字段。
3. 键盘添加事件和 payload 不变：`{ type, chartType? }`；Enter 与 Space 仍可添加。当前物料没有“单击即添加”行为，本次不新增该行为或 `click` 监听。
4. 分组折叠/展开与整个组件库面板收起行为不变。
5. 拖入画布后创建的组件类型、图表类型、默认配置、坐标和外观与本次改动前一致。
6. 不新增 API 请求、网络资源、Canvas/ECharts 实例或运行时状态。

## 5. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 默认描边、渐变、阴影叠加 | 每个条目像一张卡片，形成卡片墙 | 默认行只留中性表面；Hover 只选一种轻反馈 |
| 图标底座过大 | 长列表密度下降、滚动增多 | 图标底座控制在约 24–26px，行高控制在 36–40px |
| 固定颜色导致主题断裂 | 深色/暖色下对比或品牌色异常 | 只用现有 Token 派生，不写固定 Hex、不增全局 Token |
| CSS 影响焦点或拖拽 | 外观改动意外阻止交互 | 不覆盖元素、不改变几何位置；自动化与真实浏览器分别验证 |
| 旧设计规格范围更大 | 实施者误将画布或面板布局纳入本次 | 本计划以本次明确范围为准；不得执行旧规格中与此边界冲突的画布、面板扩宽、两列 Gallery 内容 |
| 工作区已有未提交改动 | 覆盖或误提交用户工作 | 开始前核对目标文件状态；只暂存本计划范围内文件 |
