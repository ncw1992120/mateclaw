# 洞察仪表盘：表格详情页交互设计

> 本文档记录 2026-09-22 19:00 之后确认的表格详情页、数据集查询配置、页面运行时查询、Python 预处理和数据源 Adapter 交互约定。
>
> 本文档沿用《原型设计.md》的表达方式，用于指导产品、前端、后端、Python Runner 和测试实现。若本文与旧版“字段名称 / 筛选预览”入口描述冲突，以本文为准。

## 一、设计目标

表格详情页需要支持：

- 多数据集输入；
- Aloudata 指标&维度查询；
- JDBC、接口、文件等数据源查询；
- 页面筛选器动态下推；
- 表格字段动态排序；
- 表格分页；
- Python 多数据集 Join、聚合和计算；
- Python 结果集再次筛选、排序和分页；
- 页面参数到 Python、数据集和具体数据源接口的完整传递。

本设计遵循以下原则：

1. 属性配置定义“支持什么能力”；
2. 页面运行时决定“本次查询使用什么值”；
3. Python 用户代码不直接调用 Aloudata、JDBC 或其他底层接口；
4. `datasets.read(...)` 是 Python 与数据集之间的统一读取入口；
5. 数据源 Adapter 负责把统一查询对象转换为具体数据源参数；
6. Python 系统生成区域只读，用户处理区域不被自动生成覆盖；
7. 单数据集可以尽量下推排序和分页，多数据集 Python 场景在最终结果集上排序和分页。

## 二、术语和查询阶段

### 2.1 输入数据集

用户通过“+ 添加数据集”添加的数据源结果，例如：

```text
Aloudata · 指标&维度
JDBC · db1
接口
文件 · Excel
```

每个输入数据集拥有：

- 数据集 ID；
- 数据集别名；
- 数据源类型；
- 展示字段；
- 筛选器绑定；
- 查询能力配置；
- 字段注册表；
- Python 输入名称。

### 2.2 Python 系统生成区域

由输入数据集查询配置自动生成，负责把 Runner 已准备好的输入数据集绑定到 Python 变量：

- 绑定输入数据集别名；
- 绑定字段结构；
- 调用 `datasets.read(input_name=...)` 或等价的输入数据集读取接口；
- 不再读取页面筛选参数；
- 不再在 Python 中构造数据源筛选、排序和分页参数。

数据集查询计划已经在进入 Python 前由 Runner 执行，系统区域只读，用户不能直接修改。

### 2.3 Python 用户处理区域

由用户编写业务逻辑，负责：

- Join；
- 合并；
- 聚合；
- 计算；
- 业务字段加工。

用户区域不负责拼接 Aloudata JSON、SQL 或接口 URL。

### 2.4 Python 结果集

Python 执行后产生的最终数据集。结果集不再提供一套独立的输入查询参数配置，而是由页面运行时根据组件能力执行：

- 最终结果字段展示；
- Python 计算字段排序；
- Python 结果分页；
- 必要的结果筛选。

结果集不是新的输入数据集，不进入数据源选择树，也不重新绑定 Aloudata、JDBC 或其他数据源参数。

## 三、完整交互流程

```text
添加数据集
    ↓
生成数据集卡片
    ↓
查询配置
    ↓
保存展示字段、筛选器绑定、排序能力、分页能力和入参映射
    ↓
自动生成 Python 系统区域
    ↓
用户编辑 Python 处理区域
    ↓
页面筛选器、排序、分页产生运行时 QueryContext
    ↓
Query Planner 按数据卡片配置生成输入数据集查询计划
    ↓
数据集 Adapter 转换并执行查询参数
    ↓
JDBC / Aloudata / 接口 / 文件查询
    ↓
返回已筛选 DatasetInput
    ↓
Python Runner 启动脚本，系统区域只绑定输入数据集
    ↓
Python Join、聚合和计算
    ↓
最终结果集筛选、排序和分页
    ↓
表格详情页展示
```

### 5.1 展示字段

展示字段表格负责：

- 选择当前数据集输出的字段；
- 区分维度字段和指标字段；
- 调整字段展示顺序；
- 修改展示名；
- 查看字段类型；
- 删除字段。

字段表格第一列为固定的“字段属性”，其余列为真实字段：

```text
字段属性 │ metric_date │ id │ in_account
字段名   │ metric_date │ id │ in_account
展示名   │ 指标日期    │ 编码 │ 入金客户数
类型     │ 日期        │ 维度 │ 指标
```

交互规则：

1. 字段列支持拖动调整顺序；
2. 字段列名右上角显示 `×`，点击后删除字段；
3. 技术字段名只读；
4. 展示名可编辑；
5. 展示名为空时回退为技术字段名；
6. 展示名在当前数据集内必须唯一；
7. 被筛选器绑定的字段不能直接删除，删除前需要解除绑定或确认同步清理；
8. 被允许排序的字段删除时，自动从允许排序列表移除；
9. 至少保留一个指标或维度；
10. 字段结构来自数据集字段注册表，不提供手工新增字段入口。

### 5.2 筛选器绑定

筛选器属于仪表盘级组件，字段映射属于数据集查询配置。

```text
仪表盘筛选器：策略类型
作用数据集：strategy_data
字段映射：strategy_id
状态：✓ 自动匹配
```

多个数据集时：

```text
┌──────────────┬──────────────┬────────────┐
│ 数据集        │ 字段映射      │ 状态       │
├──────────────┼──────────────┼────────────┤
│ table1        │ strategy_id  │ ✓ 自动匹配 │
│ table2        │ strategy_code│ ✓ 手动映射 │
│ table3        │ —            │ 未绑定     │
└──────────────┴──────────────┴────────────┘
```

绑定保存的是字段关系，不保存用户本次选择的筛选值。

筛选器类型自动映射：

| 筛选器 | 参数类型 | 默认运算 |
| --- | --- | --- |
| 单选 | scalar | `eq` |
| 多选 | array | `in` |
| 日期范围 | dateRange | `gte` + `lt` |
| 数值范围 | numberRange | `gte` + `lte` |
| 文本搜索 | string | `contains` |

### 5.3 允许排序字段

排序配置定义“哪些字段允许页面排序”，不保存用户当前点击的排序字段。

```text
[选择字段 ▼]

已选择：
[入金客户数 ×] [日期 ×] [编码 ×]
```

下拉列表只显示：

- 当前展示字段；
- 尚未添加的字段；
- 数据类型允许排序的字段。

第一阶段只支持单字段排序。默认不设置排序；如业务需要，可以设置默认排序。

### 5.4 分页配置

分页配置保存分页能力和限制：

```text
支持分页：开启
返回总数：是
默认每页条数：100
最大每页条数：500
```

当前页码和当前页大小属于页面运行时状态，不保存到仪表盘设计配置。

## 七、统一 QueryContext

页面操作后形成统一的运行时查询上下文：

```json
{
  "dashboardId": "dashboard-001",
  "componentId": "component-001",
  "datasetId": "ds_strategy",
  "parameters": {
    "start_date": "2026-09-01",
    "end_date": "2026-10-01",
    "strategy_ids": ["A", "B"]
  },
  "sort": {
    "field": "in_account",
    "direction": "desc"
  },
  "pagination": {
    "page": 2,
    "pageSize": 100
  }
}
```

`QueryContext` 是统一运行时对象：

- 不是 Aloudata 专属对象；
- 不是 Python 脚本对象；
- 不是前端直接拼接的 HTTP body；
- 不保存为仪表盘静态配置。

## 八、数据集查询计划和 Python 系统区域

### 8.1 查询配置生成数据集查询计划

页面筛选器、日期范围、排序和分页参数不在 Python 编辑器中配置。

它们首先由数据集卡片的“查询配置”保存为数据集查询计划：

```json
{
  "inputName": "strategy_data",
  "parameterBindings": [
    {
      "source": "dashboardFilter",
      "filterComponentId": "strategy_type",
      "field": "strategy_id",
      "operator": "in"
    },
    {
      "source": "dashboardFilter",
      "filterComponentId": "date_range",
      "field": "metric_date",
      "operator": "gte"
    },
    {
      "source": "dashboardFilter",
      "filterComponentId": "date_range",
      "field": "metric_date",
      "operator": "lt"
    }
  ]
}
```

运行时页面值与上述绑定关系合并后，由 Query Planner 生成本次数据集查询计划，并在 Python 启动前执行：

```text
页面筛选器、日期、排序、分页
        ↓
QueryContext
        ↓
Query Planner
        ↓
数据源 Adapter
        ↓
已经筛选后的 DatasetInput
        ↓
Python Runner
```

### 8.2 系统区域动态生成

查询配置保存后，系统区域只生成输入数据集绑定代码，不生成参数读取和数据源查询条件：

```python
# ===== 系统生成区域：只读 =====

strategy_data = datasets.read(
    input_name="strategy_data",
).to_polars()
```

`datasets.read(input_name="strategy_data")` 读取的是 Runner 已经按查询计划准备好的数据集。为兼容现有脚本，第一阶段保留 `datasets.read` 入口；不要求用户或系统区域再次传入 `filters`、`orders`、`limit`、`offset` 或 Aloudata 专属参数。

用户区域只负责业务处理：

```python
# ===== 用户处理区域 =====

result = (
    strategy_data
    .group_by("strategy_id")
    .agg(
        pl.col("in_account").sum().alias("total_in_account")
    )
)
```

规则：

1. 查询配置变化时，重新生成系统区域；
2. 用户处理区域保持不变；
3. 页面参数变化时，重新生成数据集查询计划并重新准备 DatasetInput，不重新生成 Python 代码；
4. 系统区域不显示参数绑定、筛选值、排序值或分页值入口；
5. 用户区域默认不读取 `params` 或 `runtime`，查询条件已经体现在输入数据集中；
6. 系统区域生成延迟沿用原型约定：用户停止修改 3 秒后生成或刷新；
7. 生成失败时保留旧系统区域和用户代码，并显示错误信息。

## 九、统一数据集查询对象

页面运行时的 Query Planner 先形成与数据源无关的查询对象，再交给数据源 Adapter 执行。Python 不负责生成这个对象；Python Runner 只接收执行完成后的 DatasetInput。

```json
{
  "datasetId": "ds_orders",
  "inputName": "orders",
  "columns": [
    "order_date",
    "strategy_id",
    "in_account"
  ],
  "filters": [
    {
      "field": "strategy_id",
      "operator": "in",
      "value": ["A", "B"]
    },
    {
      "field": "order_date",
      "operator": "gte",
      "value": "2026-09-01"
    },
    {
      "field": "order_date",
      "operator": "lt",
      "value": "2026-10-01"
    }
  ],
  "orders": [
    {
      "field": "in_account",
      "direction": "desc"
    }
  ],
  "pagination": {
    "page": 2,
    "pageSize": 100
  }
}
```

前端、Python 和数据源 Adapter 不直接互相传递 Aloudata 专属参数。查询对象在 Python 启动前由 Query Planner 生成并执行。

## 十、数据源 Adapter 转换

### 10.1 Aloudata

统一查询对象转换为：

```json
{
  "metrics": ["in_account"],
  "dimensions": ["order_date", "strategy_id"],
  "filters": [
    "[strategy_id] IN (\"A\",\"B\")"
  ],
  "timeConstraint": "([order_date] >= \"2026-09-01\" AND [order_date] < \"2026-10-01\")",
  "orders": [
    {
      "in_account": "desc"
    }
  ],
  "limit": 100,
  "offset": 100,
  "isQueryTotalCount": true,
  "queryResultType": "DATA"
}
```

字段规则：

- 展示名不进入接口请求；
- 真实字段名进入接口请求；
- 多选转换为 `IN`；
- 日期范围转换为 `timeConstraint` 或等价范围条件；
- `offset = (page - 1) * pageSize`；
- 排序字段必须在已选择的指标或维度中。

### 10.2 JDBC

统一查询对象转换为参数化 SQL：

```sql
SELECT
    order_date,
    strategy_id,
    SUM(in_account) AS in_account
FROM orders
WHERE strategy_id IN (?, ?)
  AND order_date >= ?
  AND order_date < ?
GROUP BY order_date, strategy_id
ORDER BY in_account DESC
LIMIT ? OFFSET ?
```

值通过绑定参数传递，不允许字符串拼接：

```json
["A", "B", "2026-09-01", "2026-10-01", 100, 100]
```

### 10.3 接口数据源

```http
GET /orders?strategy_ids=A,B&start_date=2026-09-01&end_date=2026-10-01&page=2&page_size=100&sort_field=in_account&sort_order=desc
```

具体参数位置由接口数据源配置决定，可以是 Query、Path 或 Body，但页面和 Python 不感知这些差异。

### 10.4 文件数据源

```text
读取文件
  → 字段过滤
  → 条件过滤
  → 排序
  → 分页
```

## 十一、单数据集和多数据集执行规则

### 11.1 单数据集

```text
页面筛选
  → Query Planner
  → 数据源 Adapter
  → 数据源过滤、排序、分页
  → DatasetInput
  → Python 可选处理
  → 页面展示
```

单数据集可以下推：

- 字段选择；
- 页面筛选；
- 时间范围；
- 排序；
- 分页。

### 11.2 多数据集 + Python

```text
页面筛选
  ├── Query Planner → table1
  └── Query Planner → table2
          ↓
      已筛选 DatasetInput
          ↓
      Python Join
          ↓
      Python 聚合
          ↓
      Python 计算
          ↓
      最终结果筛选
          ↓
      最终结果排序
          ↓
      最终结果分页
          ↓
      页面展示
```

多数据集场景规则：

- 页面筛选条件分别映射到各输入数据集并尽量下推；
- 输入数据集只读取 Python 必需字段；
- 不能把最终分页分别下推到各输入数据集；
- Python 计算字段只能在 Python 之后筛选或排序；
- 最终结果分页在 Python 处理完成后执行。

错误示例：

```text
table1 先取 100 条
table2 先取 100 条
再进行 Join
```

这会导致 Join 后结果不完整，不能作为通用实现。

## 十二、Python 结果集配置

Python 执行结果区位于 Python 编辑器底部：

```text
┌────────────────────────────────────────────┐
│ Python 预处理                               │
│                                            │
│ 系统生成区域（只读）                        │
│ 用户处理区域（可编辑）                      │
│                                            │
│ 结果集                                      │
│ strategy_result                            │
│                                            │
```

Python 结果集不再提供独立的“查询配置”入口，也不接收数据源查询参数。结果字段结构从脚本执行结果自动获取；页面排序、分页和必要的结果筛选由组件运行时根据结果字段执行。

## 十五、字段和参数校验

保存查询配置时：

1. 至少保留一个指标或维度；
2. 展示名不能重复；
3. 字段名必须存在于字段注册表；
4. 筛选器映射字段必须存在；
5. 排序字段必须属于展示字段；
6. 排序字段必须属于当前数据集的指标或维度，或被数据源声明为可排序字段；
7. `defaultPageSize` 不得超过 `maxPageSize`；
8. `pageSize` 必须在服务端最大限制以内；
9. 已被筛选器或排序引用的字段删除时必须提示影响范围；
10. Python 结果集引用不存在的字段时，显示重新绑定提示。

## 十六、Python 输入边界

Python 用户代码接收到的是已经按照数据集查询计划准备好的 `DatasetInput`，而不是页面原始参数。

系统区域示例：

```python
strategy_data = datasets.read(
    input_name="strategy_data"
).to_polars()
```

用户区域只处理输入数据：

```python
result = (
    strategy_data
    .group_by("strategy_id")
    .agg(
        pl.col("in_account").sum().alias("total_in_account")
    )
)
```

规则：

1. Python 系统区域不提供参数绑定入口；
2. Python 系统区域不提供输入筛选、排序或分页入口；
3. 用户区域默认不读取 `params` 或 `runtime`；
4. 页面参数由 Runner 在 Python 启动前应用到各输入数据集；
5. 用户代码不能覆盖页面筛选、排序和分页状态；
6. 如果未来确实需要业务计算参数，应另行定义只读业务上下文，不得与数据集查询参数混用。

## 十七、最终参数链路

```text
页面筛选器下拉选择
页面日期范围选择
表格点击排序字段
选择升序或降序
切换分页
        ↓
统一 QueryContext
        ↓
查询编排器判断下推阶段
        ↓
统一数据集查询对象
        ↓
数据源 Adapter
        ↓
JDBC / Aloudata / API / File 具体入参
        ↓
返回已筛选 DatasetInput
        ↓
Python 系统生成区域只绑定输入名称
        ↓
Python 用户处理区域
        ↓
最终结果集筛选、排序和分页
        ↓
表格详情页展示
```

注意：

```text
用户结果区入参 → 系统区入参 → 数据集入参
```

不是严格的串行传递关系。正确关系是：

```text
同一个 QueryContext
  └── Query Planner 在 Python 之前准备输入 DatasetInput
```

8. 开启分页并设置默认、最大页大小；
9. 保存后生成 Python 系统区域。

### 18.2 页面运行时查询

9. 修改筛选条件后验证页码回到第 1 页。

### 18.3 Python 预处理

1. 添加两个输入数据集；
2. 分别配置筛选器字段映射；
3. 验证两个数据集的系统区域分别生成；

## 十九、本轮交互冻结结论

1. “字段名称”入口改名为“查询配置”；
2. “筛选预览”入口改名为“查看数据”；
3. 查询配置弹窗统一包含展示字段、筛选器绑定、允许排序字段和分页；
4. 查询入参在“查看数据”弹窗中填写；
5. 页面表格表头决定当前排序字段和排序方向；
6. 第一阶段只支持单字段排序；
7. 第一次点击升序、第二次点击降序、第三次点击取消；
8. 筛选和排序变化后页码回到第 1 页；
9. 输入数据集查询配置在 Python 编辑器之前完成；
10. 查询配置保存后自动生成 Python 系统区域；
11. 页面运行参数由 Query Planner 在 Python 启动前应用到输入数据集，不注入 Python 查询参数代码；
12. Python 系统区域只读，只绑定已经准备好的输入 DatasetInput，用户区域不被覆盖；
13. 单数据集尽量下推筛选、排序和分页；
14. 多数据集 Python 场景最终排序和分页在结果集阶段执行；
15. Python 结果集底部只提供“查看数据”，不再提供独立的查询配置入口；
16. Python 结果字段结构从脚本执行结果自动获取，最终结果的排序、分页和必要筛选由组件运行时处理；
17. 数据源 Adapter 统一负责把查询对象转换为 JDBC、Aloudata、接口和文件请求；
18. 页面、Python 和数据源 Adapter 不直接互相传递具体数据源参数；
19. 查询失败保留原配置和上一次成功结果，并提供重试；
20. 查询配置中的静态能力和页面运行时状态分离保存。
