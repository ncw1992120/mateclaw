# 洞察仪表盘加载性能优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 缩短洞察仪表盘列表进入、新建、编辑和预览的等待时间，并让预览组件按各自查询完成情况渐进展示，而不是等待整条串行链路结束。

**Architecture:** 分别优化列表查询契约、创建导航、应用启动数据加载和预览运行时。列表使用轻量分页摘要接口，详情仍保留完整 Schema；预览在看板结构可用后先渲染画布，再在满足数据依赖的前提下并行查询不同组件，报告与非首屏工作不阻塞组件显示。通过轻量性能标记和真实浏览器场景验证首屏及全量完成时间。

**Tech Stack:** Vue 3、TypeScript、Pinia、Vue Router、Axios、Spring Boot、MyBatis-Plus、Vitest、JUnit 5、Codex 内部浏览器。

**Spec:** 本计划依据用户确认的仪表盘性能优化建议，以及当前实现中的 `DashboardListView.vue`、`useInsightDashboardStore.ts`、`InsightDashboardEditorView.vue`、`DashboardPreviewView.vue`、`InsightDashboardServiceImpl.java` 和 `MainLayout.vue` 请求链路。

## Global Constraints

- 保持在本地 `feature/dev_fu` 分支开发，不创建开发用 Git worktree；保留所有非本任务工作区改动。
- 保持详情读取、仪表盘编辑保存、预览筛选参数和组合卡片页签行为兼容；列表摘要接口不得替代详情接口。
- 不将仪表盘的 Python 脚本、数据集物化或报告生成作为列表/编辑器首屏的阻塞依赖。
- 并行化不能打破依赖：数据集输入物化必须先于依赖该输入的查询；同一组件不能被多个执行通道同时写入渲染状态。
- 夹具导致的 500 不属于本次性能优化范围；性能验证使用能正常返回数据的本地/浏览器夹具，不以夹具错误推导优化效果。
- 所有实现完成后必须通过 Codex 内部浏览器验证列表、新建、编辑和预览；验证后创建中文 commit 并 push `feature/dev_fu`。如环境不可用、验证失败或 push 失败，明确报告，不得宣称完成。
- 如为验证从 worktree 启动服务，记录服务归属，并在离开 worktree 前停止自己启动的服务、确认端口释放；本项目默认直接在本地分支开发。

## Review Focus

- 列表摘要漏字段导致模板/官方卡片、所有者、更新时间、缩略图或筛选计数异常；用分页、多个状态、模板可见性和空 Schema 测试覆盖。
- 列表分页后关键词搜索、状态筛选和排序只在当前页生效造成用户误以为数据丢失；用跨页匹配、筛选和排序测试覆盖。
- 新建导航与列表后台刷新发生竞争，导致新看板被旧响应覆盖或新建失败仍进入编辑器；用延迟/乱序 API 测试覆盖。
- 预览并行请求中有失败、取消或过期响应时，组件状态互相覆盖或整页停留在加载态；用混合成功/失败及筛选快速变化测试覆盖。
- Python 运行结果、管线输入和报告仍是异步依赖；确认慢脚本/慢报告不阻塞无关组件的首个结果，同时筛选刷新仍只更新绑定组件。

## 实施顺序与指标

先记录基准，再依次落地摘要列表、新建直达、应用导航按需加载，最后调整预览并行和脚本轮询。每个阶段独立通过其测试后再进入下一阶段。

对相同浏览器、相同看板和相同数据源记录以下时间，比较优化前后中位数与 P95；不以接口 500、超时夹具或空看板结果作为性能基准：

- `洞察列表可交互`：导航切换开始至列表控件可操作。
- `列表数据就绪`：开始请求至第一页摘要卡片可见。
- `创建后编辑器可交互`：点击新建至编辑器外壳和基本操作可用。
- `编辑器数据就绪`：编辑器开始加载至 Schema 完成解析、页面/组件树可操作。
- `预览首屏`：开始预览至预览外壳和组件占位出现。
- `预览首个组件出数`、`预览全部组件完成`：分别记录首个组件数据可渲染和当前页所有可查询组件结束。
