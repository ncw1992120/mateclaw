# 洞察仪表盘画布组件视觉优化实施计划

> **执行要求：** 使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项实施；步骤用 checkbox 跟踪。该计划是纯视觉改造，严禁借机修改组件功能、数据链路、Schema、编辑器布局或仪表盘以外的前端代码。

**目标：** 在不改变洞察仪表盘组件行为、输入输出、数据结果和持久化配置的前提下，优化组件进入画布后的组件外壳及真实数据呈现，包括 KPI、图表、表格、筛选器、时间筛选、AI 分析和组合卡片，使其更专业、清晰、有层次，避免边框、套卡片与「灰色标题区 + 白色内容区两张皮」造成的杂乱感。（复核注：标题重复已由现有结构解决——编辑态画布统一标题栏并向 Widget 传 `:show-title="false"`、预览态传 `:show-title="!editable"`；Task 1 截图基线时复核确认，不为此寻找模板级修改。）

**架构：** 复用当前 Vue 组件、Element Plus、ECharts 与已有 `--db-*` / `--component-*` 主题变量。实施范围限于画布 Widget 的展示层：指定 Widget 的 scoped CSS、`DashboardCanvas.vue` 中指定 Widget 外壳视觉选择器，以及 `ChartWidget.vue` 中明确列出的 ECharts 展示属性。不得新增主题机制、配置字段或运行时依赖；组件编辑画布与正式预览共用的 Widget 本体样式保持一致，但不修改预览页外壳。

**技术栈：** Vue 3、TypeScript、Element Plus、ECharts、CSS Variables、Vitest、Vue Test Utils、Playwright、Chrome CDP `9222`。

**依据：**

- `docs/superpowers/specs/2026-09-26-dashboard-component-visual-redesign-design.md` 中与画布正式 Widget 视觉相关的部分；本计划按本次确认的边界排除组件库物料面板、编辑器整体布局和其他页面。
- `对照组件实现方案` 对话最后一个 agent 回复中的画布 Widget 视觉改造范围，以及本次审美/边界评审结论。

## 1. 全局约束

- **对象边界：** 只处理从洞察仪表盘组件库拖入后，在画布/预览中渲染的正式 Widget。明确不改左侧组件物料面板 `ComponentPalette.vue`。
- **呈现边界：** 可以改变组件外观、颜色、间距、字体层级、背景、边框、圆角、阴影、图表纯视觉样式及空/加载/示例数据状态外观；不得改变内容的业务含义或交互行为。
- **不变量：** 相同仪表盘配置和相同查询结果，改造前后 KPI 值、单位和趋势，表格行列及排序分页，图表系列/数据/映射，筛选值与联动结果，AI 输入输出，保存结构，组件位置尺寸与交互结果必须相同。
- **不得修改：** 查询与 API、数据源/Dataset、数据计算、字段/系列映射、组件类型、ChartType、Schema/config/props/emits 契约、筛选和联动逻辑、AI 分析逻辑、保存/加载、复制粘贴、删除、拖拽、Resize、Grid 算法、权限。
- **范围外文件：** `ComponentPalette.vue`、`EmptyState.vue`（空态共享组件本体；空态视觉调整仅经各 Widget scoped `:deep()` 处理，且各 Widget 复用同一组拷贝值，保证空态观感跨组件一致）、属性配置面板、数据集面板/弹窗、仪表盘列表、编辑器导航/全局 Header、其他 Insight 页面、其他业务模块，以及 Preview 页面外壳。
- **运行时代码文件白名单：**
  - `mateclaw-dataagent-ui/src/views/insight/components/DashboardCanvas.vue`：只允许修改 §4 表格所列的 CSS 选择器声明。
  - `KpiCardWidget.vue`、`ChartWidget.vue`、`DataTableWidget.vue`、`FilterControlShell.vue`、`FilterSelectWidget.vue`、`TimeFilterWidget.vue`、`AiAnalysisWidget.vue`、`CombinationCardWidget.vue`：仅限各文件 `<style scoped>`；`ChartWidget.vue` 的 ECharts option 例外仅限 §5 列明的视觉属性。
  - `mateclaw-dataagent-ui/src/assets/dashboard-design.css`：默认不修改。如确需调整，仅允许 dashboard Widget 命名空间中的视觉规则，不得改全局 token 或编辑器外壳规则；先证明现有 token 不足，并由审查确认。
- **测试文件白名单：** 对应组件现有 `mateclaw-dataagent-ui/src/views/insight/components/__tests__/*` 测试，只补充或调整行为不变量测试；不得通过删测试、放宽断言来让测试通过。
- **主题：** 优先使用现有 `--db-*` 与 `--component-*` token。默认不改 `dashboard-theme.ts`；不增加 Schema 字段、预设字段或主题序列化行为。不在 Widget CSS 中散落固定 HEX。
- **审美基准：** 中性表面与数据内容为主，主题色仅小面积强调；父子层级优先用留白和浅色差。普通 Widget 不使用大面积玻璃、模糊、强光晕或持续动画；避免每一层同时有独立底色、描边、标题栏和阴影。AI 可有适度强调，但不能破坏整页克制感。
- **图表语义：** 主题不得覆盖显式系列配色和业务语义色；系列颜色、涨跌/状态不能只靠颜色传达。
- **visualStyle 优先级：** 用户在属性面板配置的 `visualStyle`（背景/边框等）经 `resolveComponentVisualStyle` 以**内联样式**挂在 `.grid-item-content` 上，**永远优先于本计划新增的任何 CSS**。实施与测试均不得使用 `!important` 覆盖用户 visualStyle；带自定义 visualStyle 的 Widget 上"新外壳 CSS 不生效"是预期行为，不是缺陷。
- **可访问性：** 正文对比度目标至少 4.5:1；焦点/选中状态清晰；控件状态不能仅以颜色区别；保留 `prefers-reduced-motion` 行为。
- **依赖：** 不新增 UI、图表、图标或动画依赖，不发起外部网络资源请求。
- **工作区：** 实施前逐项检查 `git status --short`。当前已有未提交的 `DashboardCanvas.vue` 等改动时，必须逐块识别、保留并在同一基线上实施；不得整文件覆盖、清理或回滚无关改动。只暂存本计划实际修改的文件。
- **浏览器验收：** 需使用 Codex 内部浏览器检查实际运行页面；Chrome CDP `9222` 可作为辅助验证，但不能用构建或单测代替实际视觉验收。不可用时标记 BLOCKED，不得声称浏览器验收完成。

## 2. 视觉验收标准

1. 整体先读到数据内容，装饰不压过数据；普通 Widget 的视觉层级不超过 2–3 个明显层次。
2. 相邻同类组件有一致的结构和间距；颜色变化有来源且服务于信息层级，而不是每张卡各自抢眼。
3. 标题区与内容属于统一组件表面，不出现连续的“卡中卡/框中框”；组合容器内尤其避免父边框、子边框、标题分割线层层叠加。
4. KPI 的指标名、主值、单位、趋势易于快速扫描；真实数值、负数、百分比、长值和空值均不溢出、不改变格式含义。
5. 图表坐标轴、网格、图例、Tooltip 可读，数据系列仍可区分；主题切换只改变表面/视觉，不改变系列数据与语义色优先级。
6. 表格表头、行、数字与交互状态清晰；控件标签和值仍明确，焦点可见。
7. 蓝色浅色、暖色浅色、`dark-data` 深色三类主题都无文字/边界消失、低对比或高饱和大面积铺色。
8. 编辑器画布与正式预览中的 Widget 本体样式基本一致；编辑器独有的选中框、缩放点和工具栏仍可辨识且行为不变。

## 3. Review Focus

- 同一 KPI 配置在单指标、多指标、长数值、无数据与真实数据状态下展示值/单位/趋势完全一致；由 KPI 测试覆盖。
- 图表在显式 `option.color`、多系列、自定义图表类型与空数据下，只改展示属性不改数据/映射；由 `ChartWidget.spec.ts` 覆盖。
- 表格含数字列、空值、多行、排序和分页时，内容和交互保持原样；由 `DataTableWidget.spec.ts` 覆盖。
- 组合卡片包含普通子组件、筛选/时间控件和页签时，视觉层级不套框，子组件拖拽、选择、页签、复制粘贴行为保持原样；由组合卡片测试与浏览器验收覆盖。
- 浅色、暖色、深色主题和选中/悬停/键盘焦点状态下均可读且不遮挡操作；由主题单测与 CDP 视觉矩阵覆盖。

## 5. ECharts 展示属性白名单

`ChartWidget.vue` 中若必须调整 ECharts option，仅限以下既有 option 节点的视觉字段，且需在 diff 中逐个审阅：

- `textStyle` 的 font/color；`backgroundColor`。
- `grid` 的 containLabel 与纯布局边距（不得改变数据范围/采样）。
- 坐标轴的 `axisLine`、`axisLabel`、`axisTick`、`splitLine` 的颜色、线宽、字体；可见性开关仅限 `axisLine`、`axisTick`、`splitLine` 等纯装饰元素，`axisLabel` 承载轴值默认保持可见。
- `legend` 的文字、图标、间距及位置。
- `tooltip` 的背景、边框、阴影、字体和内边距；formatter 与字段和值保持不变。
- 系列的 `lineStyle`、`itemStyle`、`areaStyle`、`symbolSize`、`emphasis` 视觉字段、柱体圆角和透明度；系列 `label` / `labelLine` 仅限颜色、字体等**纯视觉字段**，`label` 默认保持可见（它承载显示值，不得整体隐藏；formatter 与显示的数据值不变）。

禁止新增/删改 `series`、`dataset`、`data`、`encode`、`stack`、`transform`、`sort`、`sampling`、聚合方式、`visualMap` 的业务范围，禁止改变颜色所代表的正负向/分类含义。显式业务色优先级保持原状。顶层 `color` 调色板数组本计划**不动**（默认系列色保持原状；如确需调整属范围扩大，先停下报告）。
