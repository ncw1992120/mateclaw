## 1. 背景与问题

配置仪表盘时同时存在「字段名」和「展示名」两套名字，但当前实现把展示名**副本**散落存储在多个配置里（字段映射、筛选条件、KPI 指标配置、筛选器绑定推断），导致：

1. 在一处（如指标配置）改了展示名，其它地方（字段名称弹窗、筛选条件、绑定筛选器）**不会跟着变**，或要靠脆弱的回退链兜底；
2. 下推到数据源前必须把"目标名/展示名"**反解**回真实字段名（`toSourceFilters`），复杂度全是"存副本"自己长出来的；
3. 展示名若重名，按展示名找字段的逻辑会**串字段**。

定稿原则：**字段名是技术主键（不可变），展示名是表现层标签（可改）；所有引用只存字段名，展示名收敛到唯一注册表，"一处改、处处生效"由单一事实源结构性地保证，不做广播同步。**

## 2. 定稿契约（姥爷 2026-09-18 拍板 5 条）

| # | 决策 | 内容 |
|---|---|---|
| 1 | **展示名唯一** | 数据集内一个字段名 ↔ 一个展示名（双向一对一）；编辑时唯一性校验，重复即拦截 |
| 2 | **双入口、一事实源** | 「字段名称」弹窗与「指标配置」弹窗都可编辑展示名，写的是**同一份注册表** |
| 3 | **预览表头** | 默认显示展示名，悬停 tooltip 显示字段名，提供「显示字段名」开关 |
| 4 | **存量归一迁移** | 读入老配置时，把存歪的"目标名/展示名"反解回字段名并写回（惰性归一）；展示名唯一保证反解一一映射、无歧义 |
| 5 | **字段名不可变的边界** | 组件生命周期内不可变；底层 Aloudata 视图变更走 schema diff → 标记失效引用 → 提示重绑，**不允许用户改字段名** |

契约总表：

| 维度 | 字段名（name） | 展示名（displayName） |
|---|---|---|
| 本质 | 技术主键 / 契约 | 表现层标签 |
| 面向 | 后端、下推 SQL、Python 脚本、数据 Join | 用户、前端渲染、导出表头 |
| 唯一性 | 数据集内必须唯一 | 数据集内必须唯一（决策 1） |
| 可变性 | 组件生命周期内不可变（只能重绑） | 随时可改、可空（回退 name） |

**作用域语义（单一事实源的直接推论，特此写明）**：展示名注册表挂在**数据集（结果集）级**。同一数据集被多个卡片引用时，展示名修改对仪表盘内所有引用处一致生效（这正是"一处改、处处生效"的自然结果，且比"组件内各自一份"更不会出现同名不同义）。卡片级别名（override）**不在本期范围**，未来需要时再加覆盖层。

## 4. 目标架构

### 4.1 字段注册表（唯一事实源）

```ts
/** 字段注册表条目：字段名不可变，其余为展示元数据 */
export interface DatasetFieldMeta {
  name: string          // 字段名：数据集内唯一、组件生命周期内不可变（决策 5）
  displayName?: string  // 展示名：数据集内唯一（决策 1）、可空（渲染回退 name）
  description?: string  // 描述：指标业务口径 / 维度描述
  role?: string         // measure | dimension
  unit?: string         // 单位（自 kpiMetrics 收编；字段级展示配置）
}

// DatasetConfig 新增：
fields: DatasetFieldMeta[]   // 唯一事实源
```

- `ds.schema` **保留**，语义降级为"后端最近一次返回的原始清单（不可变输入）"，仅用于 diff 与重绑提示；
- `ds.fieldMapping`（`FieldMappingRow[]`）**废弃**，其三列语义由注册表覆盖：source=name、target=displayName、desc=description；
- `kpiMetrics` **保留**（它是"指标在卡片上的投影配置"：helperText/visible/自由布局/样式），但 `displayName`、`unit` **移入注册表**，kpiMetrics 上改为运行时解析（见 4.2）；
- schema 变更合并规则沿用 `buildFieldMappingRows` 的增量思想：用户改过的 displayName 保留，未改过的跟随后端最新展示名刷新；新增字段追加、消失字段移除（打失效标记，见 T9）。

### 4.2 解析规则与工具函数（`field-mapping.ts` 重写为注册表层）

```ts
/** 渲染标签：唯一的取值口径，全站只用这一个函数 */
resolveFieldLabel(fields: DatasetFieldMeta[], name: string): string   // displayName ?? name

/** 反解：展示名/旧目标名 → name（唯一性保证一一映射；未命中原样返回并记 unresolved） */
resolveFieldName(fields: DatasetFieldMeta[], ref: string): string

/** 唯一性校验：displayName 非空即可、数据集内不得重复（与 name 冲突也提示） */
validateFieldMetas(fields: DatasetFieldMeta[]): string | null

/** 按 schema 增量合并注册表（保留用户改过的 displayName/description/unit） */
reconcileFieldMetas(schema: DatasetSchemaField[], existing: DatasetFieldMeta[]): DatasetFieldMeta[]

/** 存量归一（决策 4）：把 filters/kpiMetrics 等处的旧引用归一为 name */
normalizeLegacyFieldRef(fields: DatasetFieldMeta[], legacyRows: FieldMappingRow[] | undefined, ref: string): { name: string; resolved: boolean }
```

- 现有 `resolveSourceFieldName` / `toSourceFilters` 在 T8 全部调用点清零后**删除**（连同其单测断言改写）；
- `defaultTargetOf`、`buildFieldMappingRows`、`validateFieldMappingRows` 由 `reconcileFieldMetas` / `validateFieldMetas` 取代。

### 4.3 持久化与后端契约（Phase 2 定版，后端暂不改代码）

- 前端序列化 `fieldMappings: [{source, target}]` 继续发（兼容现网），但语义定版为 **source=字段名（后端下推唯一依据）、target=展示名（仅导出表头等展示场景可用）**；
- 后端 `datasetInputs[].fieldMappings/filters` 尚未消费——**正是定契约窗口期**：后端未来实现时，pushdown 只读 source；target 仅透传给导出；
- `DatasetBatch.schema`（列名数组）= 后端视角的字段名清单，与注册表 name 一一对应，作为重绑 diff 的基准。

### Phase 2：存量迁移 + 后端契约定版

**T9 惰性归一迁移（决策 4）**
- `normalizeLegacyFieldRef` 归一顺序：① 精确=name → 保持；② =displayName → name；③ =旧 fieldMapping.target → 其 source(name)；④ 未命中 → 保留原值并收集到 `ds.unresolvedFields`；
- 触发点：`applyPipeline` / `hydratePanel` 读入时执行，**保存时写回**（完成物理归一）；`unresolvedFields` 在属性面板顶部出一条可关闭的告警（列出未识别引用，引导手动修复）；
- schema diff（决策 5）：`reconcileFieldMetas` 发现 schema 中消失的字段时，不清配置，打 `stale` 标记并在面板提示「字段已不存在，请重绑」。
- 验收：用迁移前的旧 schemaJson 打开 → 筛选条件/绑定筛选器仍指向同一字段；保存后 schemaJson 内引用全部为 name。

**T10 后端契约定版（只写文档注释，不改行为）**
