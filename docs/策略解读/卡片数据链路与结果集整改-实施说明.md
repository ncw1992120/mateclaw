# 卡片数据链路与「结果集」整改 —— 实施说明

> 日期：2026-09-18
> 关联方案：`docs/策略解读/卡片数据链路与结果集交互方案-讨论稿.md`
> 范围：`mateclaw-dataagent-ui`（前端）。未改后端。

---

## 一、整改目标

让「洞察-仪表盘-组件库-卡片-属性配置」里配好的数据**真正显示到卡片上**。

整改前的问题：数据集、筛选条件、Python 脚本都能配、也能在预览弹窗里看到数据，但卡片画布始终是空的 ——
管道配置（`component.config.datasetPipeline`）没有任何一条路径能变成卡片的渲染数据。

---

## 二、改造后的数据流

引入 **结果集** 作为一等公民：`schema + 行数 + 生成时间戳`，是卡片**唯一**的数据来源。
数据集 / 筛选条件 / Python 脚本都只是"怎么产出结果集"的手段。

```
[输入数据集] ──▶ [Python 处理（可选）] ──▶ [结果集] ──▶ 卡片
   直通（无脚本，自动）        就绪后才驱动卡片
   Python 输出（有脚本，手动）
```

### 结果集状态机

```
empty ──添加数据集──▶ stale ──生成──▶ running ──成功──▶ ready
                       ▲                 │
                       │                 └──失败──▶ failed
                       └──────配置变更──────┘
```

| 状态 | 面板表现 | 卡片表现 |
|---|---|---|
| empty | 「添加数据集后自动生成」 | 空态 |
| stale | 「已过期」+ 上次行数与时间 | **沿用上一次渲染**（不清空） |
| running | 生成中（按钮转圈） | 沿用上一次渲染 |
| ready | 字段数 · 行数 · 生成时间 · 耗时 | 用结果集渲染 |
| failed | 红色状态 + 错误摘要 | 沿用上一次渲染 |

### 触发策略（按成本分档）

| 情况 | 取数方式 | 行为 |
|---|---|---|
| 无脚本（1 个数据集） | 同步、毫秒级 | **自动**：配置变更后防抖 800ms 自动生成 |
| 有脚本（1 或 N 个数据集） | 异步 Runner + 轮询 | **手动**：等用户点「生成结果集」 |

心智模型收敛为一句话：**改完配置结果集就旧了，刷新一下就新了 —— 只是没脚本时它自己会刷。**

### 持久化（决策 B）

结果集元数据随组件 pipeline 落盘（`config.datasetPipeline.resultSet`），**行数据不落盘**：

- 有脚本：保留 `executionId`，重开仪表盘按它向后端回读结果（秒显，不重跑脚本）；
- 无脚本：回源重算（同步毫秒级，必然最新）。

| 文件 | 改动 |
|---|---|
| `InsightDashboardEditorView.vue` | 接收 `resultset` → `rowsToComponentData` 写入 `componentDataMap`；打开仪表盘时 `restoreResultSetData` 恢复；`previewAllConfiguredComponents` 排除管道卡片（避免两条取数路径互相覆盖） |
| `DashboardPreviewView.vue` | 展示态同样按结果集恢复（`reloadPipelineResults`） |

### 指标候选字段（结果集优先）

`kpiResultFields()` 改为：**有结果集 schema 时只从结果集中取字段**，结果集未产出才回退数据集注册表。
这样脚本把维度聚合掉之后，指标配置里不会再出现结果集里根本不存在的列。

### 命名拆分

整改前**两个不同层级的预览共用一个名字「筛选预览」**，用户无法区分：

| 位置 | 原名 | 现名 | 看的是 |
|---|---|---|---|
| 数据集卡片 | 筛选预览 | 查看数据 | 单个输入的原始数据 |
| 管道末端 | 筛选预览 | 预览结果集 | 最终输出 |

「预览结果集」与卡片共用同一个结果集（未就绪或已过期时先生成再展示），**预览所见即卡片所见**；
同时消除了旧实现的一个语义错误 —— 原「筛选预览」会隐式 `saveDashboard`，一个叫"预览"的按钮产生持久化副作用。

## 四、仍未完成（需后续处理）

### 1. 筛选器绑定的**运行时下推**（无脚本场景）

用户要求：「无脚本场景下，筛选器绑定直通到数据集的筛选条件中」。

- **现状**：前端已按此语义保留 `scriptFilterBindings`，面板也给出了「无 Python 脚本时，筛选条件直通到数据集的筛选条件中」的说明；
  **但实际的运行时下推尚未实现** —— 展示态恢复结果集时，`filterContext` 里的筛选值还没有被合并进数据集查询。
- **卡点**：`buildPipeline()` 写入的 `scriptFilterBindings[].filterComponentId` 是**假的占位 ID**（`filter-${i}`），
  而 `state.filterCatalog` 里才有真实筛选器 ID；`FilterBinding` 类型本身也没有存 id 的字段。
  要先补上真实 ID（`FilterBinding.filterComponentId` + 绑定弹窗落库），才能把「哪个筛选器 → 哪个数据集字段」的映射用在运行时下推上。
- **落点**：`useResultSetRestore.restoreResultSetData()` 增加可选 `filterContext`，按绑定映射把筛选值转成 `DatasetFilter` 合并进 `draftRequestForDataset` 的 filters。

### 2. 后端的 pipeline 取数

`InsightDataBindServiceImpl.bindComponent` 目前只读 `component.dataSource`，不认识 `config.datasetPipeline`。

本次通过**前端结果集链路**绕开了它（编辑态与展示态都由前端恢复数据），所以功能可用；
但若后续要做**服务端渲染、导出、定时快照**，仍需让后端认识 pipeline（或直接读结果集缓存）。

### 3. 画布上的「数据已过期」角标

面板的结果集节点会显示「已过期」，但画布卡片本身**没有视觉标记**（只是沿用旧数据）。加角标需要改 `DashboardCanvas`。

### 4. 组件 `boundFilterIds` 未由属性面板写入

属性面板的「筛选器绑定」只写 `scriptFilterBindings`，没有回写 `component.boundFilterIds`，
因此后端 `previewData(filterContext)` 的"作用范围"判断对管道组件不生效。属于既有缺口。
