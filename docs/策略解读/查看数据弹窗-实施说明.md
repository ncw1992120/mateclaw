# 「查看数据」弹窗改造 — 实施说明

> 起因：属性配置里点「查看数据」后，**没有让用户添加筛选条件的地方**，数据却直接出来了。
> 期望流程：用户添加维度筛选条件 → 点确定/查询 → 条件下推到源查询 → 出过滤后的结果。
> 另外取消上一版的全屏「工作台」形态，改回弹窗。

## 一、形态：全屏工作台 → 弹窗

| | 上一版 | 现在 |
|---|---|---|
| 容器 | `position:fixed; inset:0` 全屏覆盖 | `el-dialog`（1020px · top 5vh） |
| 组件 | `DataWorkbench.vue`（已删除） | `DatasetDataDialog.vue` |
| 状态 | `ui.workbench` | `ui.dataDialog` |
| 入口函数 | `openWorkbench` / `closeWorkbench` | `openDataDialog` / `closeDataDialog` |

弹窗内三段：

```
定义        ← SQL 可编辑 / 指标视图 / 接口 / 文件信息（只读）
筛选条件    ← 字段 + 操作符 + 取值
            ← [+ 添加筛选条件]（条件行下方，左对齐）
            ← 提示 …… [查询]（右侧）
结果        ← 表格，滚动到底按 offset 加载下一页
```

> **没有 footer**（按用户要求删掉「关闭 / 查询」footer）：「查询」移到筛选条件正下方 —— 改完条件顺手点，视线不用跳到弹窗底部；
> 关闭只靠右上角 ✕ 与 ESC。「查询」不放 footer 另有一层原因：footer 里的按钮通常意味着「保存并关闭」，
> 而这里的结果要留在弹窗内看。
>
> **「添加筛选条件」也放在下方**（用户要求）：在条件行与「查询」之间、左对齐 —— 铺条件的动作发生在查询之前，
> 两个按钮的纵向顺序与操作顺序一致。区块头只留标题，不再放按钮。
>
> 文件类型没有筛选条件区块，「查询」行仍会出现在定义区与结果区之间（提示改为「文件类型暂不支持筛选下推，直接查询即可」），
> 保证任何类型都有查询入口。

## 二、关键行为变更

### 1. 打开弹窗不取数

上一版 `void run()` 在挂载时立刻执行，所以「一打开数据就出来了」。
现在打开只做初始化（铺定义 / 铺参数 / 回填条件），结果区显示 **「点「查询」获取数据」**，必须点「查询」才发请求。

> 按钮叫「查询」而不是「确定」：`确定` 在弹窗 footer 里通常意味着「保存并关闭」，
> 而这里的结果要留在弹窗内看，所以用更贴切的「查询」，且不关闭弹窗。

### 2. 补回筛选条件构造器（本次核心）

`InputFilterDialog` 上一轮被删掉后，**筛选项一度无处可配** —— 这次以「筛选条件」区块的形式回到弹窗里：

- 每行：字段下拉 + 操作符下拉 + 取值输入 + 删除
- 「+ 添加筛选条件」新增行；无存量条件时预置一条空行，打开即能填
- 字段下拉 `filterable + allow-create`：取不到字段清单时可直接敲字段名

**字段候选按数据源类型给**：

| 类型 | 可筛选字段来源 |
|---|---|
| Aloudata 指标视图 | `GET /datasources/{id}/analysis-views/{viewName}/fields` 里的**维度**（指标是聚合结果，不作为筛选项） |
| Aloudata 指标&维度 | 已选维度 `ds.aloudata.dims` |
| JDBC / 接口 | 字段注册表 `ds.fields`；为空时回退文件列，仍为空则提示手输 |
| 文件 | **不给筛选入口** —— 后端 `previewFile` 只把 filters 记进 `residualFilters`，不做下推，给了就是「能配但不生效」 |

**操作符按数据源类型给**（`utils/filter-conditions.ts`）：

- 维度筛选：`=`、`!=`、`in`、`not in`、`between`、`>`、`>=`、`<`、`<=`
  —— 不含 `contains` / `is null`：Aloudata 语义层只接受 `= <> > >= < <= IN NotIn`，带上会被服务端拒绝
- JDBC / 接口：再加 `contains`（包含文本，值自动补 `%`）、`is null`、`is not null`

### 3. 条件写回 `ds.filters`（换界面，不换存储）

查询时把完整条件写回 `ds.filters`（沿用既有的 `{field, op, value}` 契约，**未改持久化格式**），
这样卡片后续取数用的是同一份条件，符合「预览所见 = 卡片所见」。

字段已不在当前可筛选项内的存量条件，单独列成**「遗留条件」**（可见、可移除，不静默丢弃）。

### 4. 保留最近一次执行结果（条件 + 数据）

关掉弹窗再打开，**上次的筛选条件和结果数据都还在**，不用重新点「查询」：

- **条件**：本来就写回 `ds.filters`，打开时回填（见上）
- **结果**：新增会话级缓存 `components/dataset-data-cache.ts`，按数据集 id 记
  `{rows, columns, hasMore, elapsed, queriedAt, signature}`；查询成功（含滚动追加页）即写入，打开时恢复
- **条件被改过**：结果照常展示，结果区标注 **「条件已变更，点「查询」刷新」** —— 不静默丢弃，也不假装它还是最新的
  （`signature` = SQL + 参数值 + 条件行 + 遗留条件的指纹，与缓存时不一致即视为过期）
- **只放内存、不进 schema**：行数据可能很大，落进 `DatasetConfig` 会跟着仪表盘持久化，体积与语义都不对；
  刷新页面后回到空态，这是有意的取舍

### 5. 走位修正：先写回再构造请求

`draftRequestForDataset()` 是从 `ds.filters` 取 filters 的。原先 `persistConditions()` 写在构造请求**之后**，
导致刚改的条件第一次查询时丢失（第二次才生效）。现在把写回提到构造请求之前。
**这个 bug 是写组件测试时被断言抓出来的**，不是靠看代码看出来的。

## 五、遗留

1. 结果表表头显示的是**字段名**（`metric_time`）而不是展示名（`指标日期`）—— 属字段名/展示名契约的既有边界，本次未动。
2. 文件类型没有筛选下推能力（后端 `previewFile` 不支持），需要后端补齐才能给入口。
3. 指标视图模式的「维度」在定义区显示为空是正常的：该模式只选视图，不单独选维度；筛选项来自视图定义里的维度。
