# 表格详情页查询链路实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行。每个任务都必须完成对应测试并更新本计划的复选框。

**目标：** 根据《表格详情页交互设计.md》，打通“页面筛选/排序/分页 → Query Planner → 数据集 Adapter → Python `datasets.input(...).to_polars()` → 结果集展示”的真实链路，并让前端、DataAgent 后端和 Python Runner 使用同一套查询与输入契约。

**架构：** 前端将数据卡片查询能力保存在组件 `config.datasetPipeline.datasetInputs`，本次筛选、排序、分页只形成 `QueryContext`；DataAgent 在执行前合并两者形成每个输入的查询计划，由现有 Adapter 执行后固化受控的 prepared input。Runner 仅凭任务令牌和 `inputName` 读取它；Python 系统区只生成 `datasets.input(input_name="...").to_polars()`，脚本最终结果再执行必要的结果级筛选、排序、分页。单数据集不启用脚本时走相同的 Query Planner/Adapter，但跳过 Runner。

**技术栈：** Vue 3 + TypeScript + Vitest + Playwright/CDP 9222；Spring Boot + Java 21 + Maven + JUnit 5/Mockito；Python 3 + pytest + Polars/Pandas 兼容 `DatasetInput`；WireMock/本地 Aloudata 模拟环境。

**规格依据：** [表格详情页交互设计.md](../表格详情页交互设计.md)。实现过程中若与旧版“字段名称 / 筛选预览”入口冲突，以该设计文档和本计划为准。

## 全局约束

- Python 系统区域只能由系统生成，标准读取方式是 `datasets.input(input_name="strategy_data").to_polars()`。
- `datasets.input(...)` 返回的是已经完成数据卡片查询配置、页面筛选器、展示字段及适用下推处理的 `DatasetInput`，不是原始数据源结果。
- Python 系统区域不读取 `params`、`runtime`，不重新拼接 `filters`、`orders`、`limit`、`offset` 或 Aloudata 专属参数。
- 现有 `DatasetClient.read(input_name, columns, filters)` 是可再次查询数据源的旧入口，并非语义等价的 prepared-input 别名。第一阶段保留旧脚本兼容但不生成新调用；应有迁移告警和防止绕过页面筛选的服务端策略。执行者不得简单将 `read` 重定向到 `input` 破坏旧脚本。
- 字段映射、筛选、排序和分页使用数据源字段名，不使用用户修改后的展示名。
- 单数据集尽量下推筛选、排序和分页；任意会改变行数、粒度或顺序的 Python 脚本，以及多数据集脚本，最终排序和分页必须放在结果集阶段；筛选条件仍在每个被绑定的输入读取前应用。
- 数据源 Adapter 只允许读取；JDBC 继续使用只读 SQL 校验和参数绑定，禁止写操作。
- 所有数据集和仪表盘请求都重新校验 workspace、组件和数据集归属；前端不能成为权限边界。
- 不把数据库密码、Aloudata UID、JWT 或其他认证值写入代码、测试 fixture 或日志。
- 后端使用 Java 21；DataAgent 按仓库规范先安装父 POM、`mateclaw-sdk`，再执行 DataAgent 测试。
- 本计划不引入 DuckDB、Trino、pip install 或新的外部运行时依赖。

## 评审重点

1. 页面筛选器传入 `date_range`、多选 `in`、单选 `eq` 时，字段映射和下推语义必须一致；由任务 2、任务 3 的多类型过滤测试覆盖。
2. 表格用户在 A 升序后切换 B 字段，再依次点击 B 降序、取消，必须使用本次表头状态；旧请求晚返回不得覆盖新结果，由任务 5、任务 9 的状态及延迟响应测试覆盖。
3. Aloudata、JDBC、HTTP、文件四种 Adapter 的请求形态不同，但必须返回相同的 `DatasetBatch`/`DatasetInput` 契约；由任务 2、任务 8 的 WireMock/Adapter 测试覆盖。
4. Python 脚本读取空结果、结果超过内联大小、输入别名非法或已过期令牌时，必须是可解释的局部失败；ObjectRef 不得被截断预览充当完整 `to_polars()`，由任务 4、任务 7 的 SDK/安全测试覆盖。
5. 查询配置保存后重新打开编辑器，字段注册表、筛选器绑定、排序能力、分页能力和系统区域代码必须一致；删除被绑定字段需提示并同步解除，系统区 3 秒防抖失败时不得覆盖用户代码，由任务 5、任务 6、任务 9 覆盖。

## 统一接口契约

### 0. 仪表盘静态配置的归属与迁移

查询能力保存在 `pages[].components[].config.datasetPipeline.datasetInputs[]` 对应输入之下，不存本次用户所选的筛选值和页码。第一阶段新增 `queryConfig`，一个输入的最小配置如下：

```json
{
  "datasetId": "42",
  "inputName": "strategy_data",
  "queryConfig": {
    "displayFields": [
      {"field": "metric_date", "title": "指标日期", "role": "dimension", "dataType": "date"},
      {"field": "strategy_id", "title": "策略编码", "role": "dimension", "dataType": "string"},
      {"field": "in_account", "title": "入金客户数", "role": "measure", "dataType": "number"}
    ],
    "parameterBindings": [
      {"filterComponentId": "strategy_type", "parameterName": "strategy_ids", "field": "strategy_id", "operator": "in"},
      {"filterComponentId": "date_range", "parameterName": "start_date", "field": "metric_date", "operator": "gte"},
      {"filterComponentId": "date_range", "parameterName": "end_date", "field": "metric_date", "operator": "lt"}
    ],
    "sortPolicy": {"enabled": true, "mode": "single", "allowedFields": ["in_account"], "defaultSort": null},
    "paginationPolicy": {"enabled": true, "defaultPageSize": 100, "maxPageSize": 500, "returnTotalCount": true}
  }
}
```

`datasetId` 在前端 Schema 中须是已存在的真实数据集 ID；本计划固定样例使用 `"42"`，不可将设计文档中的概念标识 `ds_strategy` 直接发往现有 Java `long datasetId` 接口。旧版 `fieldMappings.source/target` 仍分别表示技术字段名/展示名；读入旧 Schema 时只在编辑器的归一化层将 `scriptFilterBindings` 转成 `queryConfig.parameterBindings` 的展示草稿，未经用户确认不得静默改变已发布仪表盘的执行结果。保存新版后以 `queryConfig` 为本组件输入的权威配置，旧 `scriptFilterBindings` 仅供旧版读取兼容，禁止两份规则同时生效。

### 1. 页面运行时 `QueryContext`

```json
{
  "dashboardId": "dashboard-001",
  "componentId": "component-001",
  "datasetId": "42",
  "parameters": {
    "strategy_ids": ["A", "B"],
    "start_date": "2026-09-01",
    "end_date": "2026-10-01"
  },
  "sort": {"field": "in_account", "direction": "desc"},
  "pagination": {"page": 2, "pageSize": 100},
  "requestId": "run-20260922-001"
}
```

这与设计文档第七节同形；`requestId` 是本计划补充的链路关联标识，不属于持久化配置。`datasetId` 仅用于数据卡片“查看数据”，组件执行时可省略并由服务端根据组件绑定的数据集逐个生成计划。`parameters` 的键必须来自已绑定筛选器的参数定义，客户端不得通过自造 `field/operator` 改写查询模板。日期范围按保存的绑定展开为 `gte(start_date)` 与 `lt(end_date)`，数值范围才是 `gte/lte`；空选/“全部”是无过滤，只有业务上明确的空集合才短路为空结果。`pagination.page` 从 1 开始，最大每页条数必须同时满足配置和服务端上限；首轮服务端上限为 500。未开启分页/总数时不能返回虚假的精确总数。

### 2. 数据集查询计划

```json
{
  "datasetId": "42",
  "inputName": "strategy_data",
  "columns": ["metric_date", "strategy_id", "in_account"],
  "filters": [
    {"field": "strategy_id", "operator": "in", "value": ["A", "B"]},
    {"field": "metric_date", "operator": "gte", "value": "2026-09-01"},
    {"field": "metric_date", "operator": "lt", "value": "2026-10-01"}
  ],
  "orders": [{"field": "in_account", "direction": "desc"}],
  "pagination": {"page": 2, "pageSize": 100},
  "pushdown": {"filters": true, "sort": true, "pagination": true},
  "residualOperations": []
}
```

`pushdown` 是服务端计算结果，不允许前端伪造。计划的数据源字段名来自已保存的 `parameterBindings` 和字段注册表，不来自临时 `parameters` 的任意键名。多数据集 Python 场景中，最终排序/分页不下推到任一输入，即使排序字段同时存在于两个输入中也不例外；脚本计算字段的最终排序和必要结果筛选由结果集服务处理。数据源不支持的操作必须有有界残余处理，否则明确失败，不可只返回标志而丢失语义。对于单数据集页面请求第 2 页，该计划转为数据源 `limit=100,offset=100`；Python 脚本若改变结果集粒度则不允许做此转换。

### 3. Python 系统区域

系统生成的唯一标准样例：

```python
# ===== 系统生成区域：只读 =====
strategy_data = datasets.input(
    input_name="strategy_data",
).to_polars()

# ===== 用户处理区域 =====
result = (
    strategy_data
    .group_by("strategy_id")
    .agg(pl.col("in_account").sum().alias("total_in_account"))
)
```

`datasets.input(...)` 返回的 `DatasetInput` 已经是查询计划处理后的输入。用户代码只能读取它并执行 Join、聚合和计算，不得直接拼接数据源 URL、Aloudata JSON 或 SQL。

Runner 内部读取成功响应的最小示例（位于现有 `R<T>.data` 中）：

```json
{
  "inputName": "strategy_data",
  "schema": [{"name": "strategy_id", "dataType": "STRING"}, {"name": "in_account", "dataType": "DECIMAL"}],
  "rowCount": 2,
  "rows": [{"strategy_id": "A", "in_account": 120.5}, {"strategy_id": "B", "in_account": 80.0}],
  "objectRef": null
}
```

大结果采用同一 schema 与 rowCount，但 `rows=null, objectRef={...}`；SDK 必须用受控批量读取取得完整行集后才可调用 `to_polars()`。如果无法在安全限制内读取，显式返回资源超限错误，不允许以“前 10 行预览”冒充完整结果。

### 4. 后端端点

| 端点 | 方法 | 用途 | 请求/响应关键字段 |
| --- | --- | --- | --- |
| `/dataagent/api/v1/datasets/query-plan/preview` | POST | 编辑器验证单个数据集计划 | 请求 `datasetId/inputName/queryContext` 和尚未保存时的受校验配置草稿；响应 `plan/pushdownReport/descriptor/rows/totalCount?`；预览不落库 |
| `/dataagent/api/v1/insight/dashboards/{id}/components/{componentId}/executions` | POST | 组件正式执行（复用现有路径） | 请求 `queryContext/schemaJson?`；存量 `parameters` 仅用于兼容旧调用；响应 `executionId/status` |
| `/dataagent/api/v1/insight/dashboards/executions/{executionId}/result/preview` | POST | 结果集筛选/排序/分页 | 请求 `sort/pagination/parameters?`；响应 `columns/rows/totalCount?/page/pageSize`，不得从旧接口前 10 行截取后再分页 |
| `/dataagent/api/internal/v1/script-tasks/{taskId}/datasets/input` | POST | Runner 读取 prepared input | 请求只含 `inputName`；响应 `DatasetBatch` 或 `ObjectRef` 分页批次 |
| `/dataagent/api/internal/v1/script-tasks/{taskId}/datasets/read` | POST | 旧脚本兼容 | 保留现有 `columns/filters/limit/offset`，新系统代码不使用 |

上述前三个新/扩展接口复用已有鉴权与 `R<T>` 信封；Runner 内部接口校验任务令牌。建议在现有异常封装中统一映射稳定业务错误码：`QUERY_CONTEXT_INVALID`、`FIELD_NOT_ALLOWED`、`SORT_NOT_ALLOWED`、`PAGE_SIZE_EXCEEDED`、`DATASET_ACCESS_DENIED`、`PREPARED_INPUT_EXPIRED`、`RESULT_NOT_READY`，并为已有 `R` 格式加契约测试。完整请求 URL 的 `/dataagent/api` 是部署 context path，Controller 注解不再重复该前缀。

## 最终验收标准

### 功能验收

- 用户能在数据卡片“查询配置”中完成展示字段、筛选器绑定、允许排序字段和分页配置。
- 用户能在“查看数据”中输入本次实际筛选值，并看到真实结果、总数、排序和分页。
- 页面表格排序会更新 QueryContext，并按当前数据集能力下推或进入 residual 结果处理。
- Python 系统区域生成并执行 `datasets.input(input_name="...").to_polars()`；读取数据已是参数处理后的结果集。
- Python 多数据集 Join、聚合和计算后，结果区仍能独立查看、筛选、排序和分页。
- Aloudata 指标&维度、JDBC、HTTP、文件四类输入遵循统一 DatasetBatch/DatasetInput 契约。

### 质量验收

- 后端 JUnit、Python pytest、前端 Vitest、Playwright/CDP 用例均有实际执行证据。
- `mvn ... test`、`pytest`、UI typecheck/build 均通过；未运行项有明确原因。
- 无明文凭据、无跨 workspace 读取、无 JDBC 写操作、无任意 URL 访问。
- 错误、空结果、超时、超大结果和令牌过期均有稳定错误码和可恢复提示。
- 视觉验收覆盖配置弹窗、查看数据弹窗、结果列表、错误状态和编辑器重新加载，差异不通过无依据放宽阈值解决。

### 验收路径

1. 使用本地模拟环境和固定 fixture 启动 UI/DataAgent/Runner。
2. Chrome 通过 CDP `9222` 进入洞察仪表盘，创建或打开表格组件。
3. 添加 Aloudata 指标&维度数据集，配置字段、筛选器绑定、排序字段和分页。
4. 在页面选择日期范围、多选策略类型，点击表头排序并翻页。
5. 检查 Network 中 QueryContext、DataAgent 查询计划、Aloudata 请求及响应摘要。
6. 打开 Python 编辑器，确认系统代码是 `datasets.input(...).to_polars()`；执行 Join/聚合脚本。
7. 在结果区查看数据、切换排序和分页，确认最终结果与预期聚合一致。
8. 保存、刷新、重新打开仪表盘，确认配置和系统代码回显。
9. 保存证据并按 `PASS/FAIL/BLOCKED/NOT_RUN` 出具报告。

## 实施完成定义

只有同时满足以下条件才能将计划标记为完成：

1. 任务 1 至任务 10 的复选框全部完成，且没有未解释的失败项。
2. `datasets.input(...)` 新契约和 `datasets.read(...)` 历史读取契约均有测试；新系统模板不再生成 `read`，历史读取不能绕开强制页面过滤。
3. 页面运行时参数、数据集计划、数据源请求、Python 输入和结果集预览均有同一 `requestId/executionId` 可追踪。
4. 至少完成 Aloudata + JDBC 双源真实模拟联调；HTTP/File 至少完成 Adapter 单测和模拟接口联调。
5. Chrome CDP 9222 视觉验收完成并保存截图；浏览器不可用时必须明确标记阻塞，不得宣称验收通过。
6. 仅提交本计划范围内的代码、测试、fixture 和证据，完成 `git diff --check`，中文 commit，并验证远端 SHA 与本地一致。
