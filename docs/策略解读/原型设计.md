# 洞察仪表盘：组件数据配置原型

> 本文档是基于 `design.md` 的交互原型粗稿，用于表达“组件如何添加数据源、配置查询、预览数据、进行多数据集处理以及绑定筛选器”。

## 一、整体交互流程

1. 卡片属性配置面板按以下顺序展示：

```text
属性配置
├── 组件标题
├── 多指标模式
├── 多TAB模式
├── + 添加数据集
├── 筛选器绑定
├── 编辑Python脚本
```
- 本文档当前以“KPI/指标卡”为例；只有选中“KPI/指标卡”时才显示“多指标模式”和“多TAB模式”。
- “筛选器绑定”绑定到当前选中的“KPI/指标卡”，不再提供独立的“组件级时间筛选”。
- 除“+ 添加数据集、Python 预处理”外，其他交互沿用原版，原版是指 dataagent远程分支的版本；本节顺序是当前卡片属性配置的唯一顺序依据。

## 二、添加数据集

组件配置面板中提供：

```text
+ 添加数据集
```

点击“+ 添加数据集”后打开数据源选择树。
支持树形结构逐级展开：点击分类节点只展开或收起，点击叶子节点才进入对应配置流程。数据源选择树如下：

```text 
├── Aloudata
│   ├── 指标视图
│   └── 指标&维度
├── JDBC
│   ├── db1
│   └── db2
├── 接口
└── 文件
    ├── Excel
    ├── CSV
    ├── TXT
    ├── JSON
    └── Parquet
```

用户点击数据源后，打开对应的弹窗或编辑器，完成该数据集的配置。


## 三、单个数据集配置

每个已经添加的数据集都以一个独立配置表单展示：

```text
┌────────────────────────────────────────┐
│ 数据源：JDBC · db1                      │
│ 数据集别名：[table1]                     │
│ [字段名称] [筛选预览] [移除]              │
└────────────────────────────────────────┘
```

其中：

- “数据源”点击数据源可以弹窗该数据源对应的弹窗或编辑器，进行重新配置编辑
- “数据集别名”用于在后续 Python/SQL 处理时引用该数据集；
- “字段名称”用于查看和配置源字段名称到目标字段名称的映射；
- “筛选预览”用于配置本次数据集查询的筛选条件，预览当前数据集，不需要等待其他数据集配置完成；
- “移除”只移除当前组件配置中的引用，不删除真实数据源。

### 3.1 JDBC 数据集

选择 `JDBC · db1` 后，显示“输入 SQL”入口：

```text
JDBC · db1

[输入 SQL]
```

点击后打开 SQL 编辑器弹窗：

```text
┌────────────────────────────────────────┐
│ 输入 SQL                                │
├────────────────────────────────────────┤
│                                        │
│             SQL 编辑器                  │
│                                        │
│                                        │
├────────────────────────────────────────┤
│ [取消] [筛选预览] [执行记录] [确定]        │
└────────────────────────────────────────┘
```

交互规则：

1. SQL 必须是只读查询；
2. 只允许 `SELECT` / `WITH` 查询，不强制 SQL 必须包含 `WHERE`；
3. SQL 参数使用绑定方式，不使用字符串拼接；
4. 点击“筛选预览”时，用户先填写本次实际筛选条件值，系统再执行受限预览；
5. 点击“筛选预览”或停止修改 SQL 3 秒后，系统自动生成或刷新数据集表单，不需要额外的确认按钮；
6. 点击“确定”后，将 SQL 查询定义保存为当前输入数据集；
7. 写入语句、多语句、危险函数和超过资源限制的查询由后端拒绝。

SQL确认后关闭“数据源选择树”并返回数据集表单：

```text
┌────────────────────────────────────────┐
│ 数据源：JDBC · db1                      │
│ 数据集别名：[table1]                     │
│ [字段名称] [筛选预览] [移除]              │
└────────────────────────────────────────┘
```


“+ 添加数据集”移动到当前数据集表单下方。

## 四、字段名称和输入筛选

### 4.1 修改字段名称

点击“修改字段名称”后打开字段映射弹窗：

```text
┌────────────────────────────────────────┐
│ 修改字段名称                           │
├────────────────────────────────────────┤
│ 字段名            字段描述       目标名称  │
│ strategy_id      策略 ID       策略 ID   │
│ event_date       事件日期       事件日期   │
│ delivery_count   下发次数       下发次数  │
├────────────────────────────────────────┤
│ [取消] [确定]                          │
└────────────────────────────────────────┘
```

字段行由数据集 schema 自动生成，不提供手工新增入口：

- 数据集配置确定后，系统自动预取该数据集的字段结构（字段名 + 显示名）并填入弹窗；打开弹窗时若尚无字段缓存，再实时拉取一次作为兜底。
- “字段名”为数据集真实字段名，只读；“字段描述”为字段显示名（无显示名时为空），只读；“目标名称”可编辑，默认取显示名，无显示名时取源字段名。
- 重新拉取 schema 时按字段名增量合并：用户改过的“目标名称”保留，未改动的跟随最新显示名刷新，新增字段追加、消失字段移除。
- 未取到字段结构时弹窗显示空态提示并提供“重新获取字段”，不提供手工新增字段。

最终数据集中的字段名称以“目标名称”为准。后续筛选器绑定字段时，应使用最终数据集字段名称。
输入筛选等条件真正下推到数据源时，使用“目标名称”反解出的源字段名，避免重命名后的字段名下推到源库报错。

### 4.2 输入筛选

点击“输入筛选”后打开筛选配置弹窗：

```text
┌────────────────────────────────────────┐
│ 输入筛选                               │
├────────────────────────────────────────┤
│ 字段                    过滤条件        │
│ event_date              [最近 30 天 ]   │
│ status                  [= ACTIVE   ]   │
│                                        │
│ [添加筛选条件]                         │
├────────────────────────────────────────┤
│ [取消] [确定]                          │
└────────────────────────────────────────┘
```

输入筛选属于当前数据集的查询条件，应尽可能在源数据查询阶段执行，以减少返回数据量。

## 六、筛选器绑定（Python 之前）

数据源和输入筛选配置完成后，必须先完成筛选器绑定，再进入 Python 编辑器。绑定结果会用于生成 Base Script，并作为查询时向各输入数据集下推筛选条件的依据。

```text
绑定筛选器 [选择筛选器]
```

筛选器的作用范围由用户选择：

```text
筛选器：策略类型

作用范围：
☑ 数据集table1
☐ 数据集table2
☑ 数据集table3
```

绑定时需要使用最终数据集中的字段名称。系统可以提供自动匹配和手动映射，但不能假设所有数据集字段名称都相同。

```text
仪表盘参数：strategy_id

数据集table1：strategy_id     ✓ 自动匹配
数据集table2：strategy_code   ⚠ 需要手动映射
数据集table3：策略 ID           ✓ 自动匹配
```

完成绑定后，系统提供：

```text
[编辑 Python 脚本]
```

绑定配置是实际执行依据，Base Script 是供用户阅读和继续开发的基础代码。用户修改筛选器绑定后，只更新系统生成区域，不覆盖用户已经编写的处理逻辑。

## 七、数据集预处理

显示：

```text
[编辑 Python 脚本]
```

如果只有一个数据集，Python 预处理是可选的；如果有两个及以上数据集，Python 预处理为必填项，否则多数据源图表或 ECharts 无法形成最终数据集。

点击后打开 Python 编辑器：

```text
┌────────────────────────────────────────┐
│ 编辑 Python 脚本                       │
├────────────────────────────────────────┤
│                                        │
│             Python 编辑器              │
│                                        │
├────────────────────────────────────────┤
│ [取消] [筛选预览] [执行记录] [确定]     │
└────────────────────────────────────────┘
```

Python 编辑器分为系统生成区域和用户处理区域：

```text
┌────────────────────────────────────────┐
│ 系统生成区域                           │
│ 输入数据集、筛选器参数、字段映射        │
│ 只读 / 可重新生成                       │
├────────────────────────────────────────┤
│ 用户处理区域                           │
│ 用户编写 Join、合并、计算和业务规则      │
│ 可自由编辑                             │
└────────────────────────────────────────┘
```

Base Script 引用前面配置的数据集别名，并展示筛选器映射：

```python
# ===== 系统生成区域：输入数据集和筛选绑定 =====

strategy = inputs["table1"]
users = inputs["table2"]

# strategy_id → table1.strategy_id
# strategy_id → table2.strategy_code
# 绑定筛选条件将在数据源查询阶段下推

# ===== 用户处理区域 =====

result = strategy.join(users, on="user_id")

return result
```

用户可以直接基于 Base Script 继续开发，但不建议让用户手动修改系统生成区域。修改筛选器绑定后，系统提示用户选择：

```text
筛选器绑定发生变化，Base Script 的系统区域需要更新。

[重新生成系统区域] [暂不更新]
```

Python 数据集采用惰性执行：保存的是输入数据集、参数映射和处理逻辑，只有用户点击预览或仪表盘执行查询时才真正运行。

```text
筛选条件传入 PyDataset
    ↓
分别下推到各输入数据源
    ↓
JDBC/Aloudata 返回过滤后的数据
    ↓
Python 执行 Join、合并和计算
    ↓
返回最终数据集
```

Python 处理完成后形成当前卡片的最终结果，供组件展示：

```text
┌────────────────────────────────────────┐
│最终结果                                  │ 
│[字段名称] [筛选预览] [移除Python脚本]       │
└────────────────────────────────────────┘
```

其中：

- “字段名称”用于查看和配置源字段名称到目标字段名称的映射；
- “筛选预览”用于配置本次结果集查询的筛选条件，默认把“绑定筛选器”的字段带过来，出现弹窗让用户配置筛选值，预览当前结果集；
- “移除 Python 脚本”只移除当前卡片的用户处理脚本，不删除输入数据集。


## 八、预览状态和执行反馈

预览分为三种：

### 当前数据集预览

只执行当前数据源的查询，查看源数据结果。

### 预处理结果预览

执行所有输入数据源查询，再执行 Python 处理，查看最终数据集。

### 组件展示预览

将最终数据集交给当前卡片、图表或表格，查看真实组件效果。

预览结果必须包含以下 Tab：

```text
[数据预览] [字段结构] [执行信息] [处理日志]
```

执行信息至少显示：

- 输入数据集名称；
- 实际查询条件；
- 已下推的筛选条件；
- 扫描量和返回量；
- Python 处理耗时；
- 输入行数和输出行数；
- 错误信息和处理节点。

## 九、最终组件配置结果

最终规则：

1. JDBC 选择数据库资源后配置 SQL，不强制选择表；
2. Aloudata 支持“指标&维度”和“指标视图”；
3. 每个输入数据集都可以独立配置筛选和预览；
4. 多数据集必须经过预处理形成一个最终数据集；
5. 筛选器作用范围由用户选择；
6. Python 只保存处理逻辑，预览或查询时才执行；
7. 外部筛选参数先下推到各输入数据源，再执行 Python 处理。

## 十、卡片属性配置页面约束

本节用于明确卡片属性配置页面的固定结构、显示条件和禁止项，避免将内部实现状态误设计为用户交互。

### 10.1 原型文档的约束级别

本文档是卡片属性配置页面的唯一交互依据。实现必须遵循本文档中定义的页面结构、显示条件、交互顺序和禁止项。

未在本文档中定义的用户界面元素不得自行增加。内部状态、历史兼容字段和服务端实现细节不得直接暴露给用户；如确实需要新增用户交互，必须先更新本文档，再进行开发。

### 10.2 页面上下文

用户从以下路径进入卡片属性配置：

```text
洞察 → 仪表盘 → 选择卡片 → 属性配置
```

进入页面后，当前选中的卡片就是当前配置目标。当前卡片同时是：

- 数据集配置目标；
- Python 最终结果接收目标；
- 预览结果展示目标；
- 保存和发布目标。

用户不需要再次选择目标卡片，也不需要配置结果绑定组件。

### 10.3 页面固定结构

卡片属性配置面板按以下顺序展示：

```text
属性配置
├── 组件标题
├── 多指标模式（仅 KPI/指标卡）
├── 多TAB模式（仅 KPI/指标卡）
├── 添加数据集
├── 筛选器绑定
└── Python 预处理
```

本文档当前只讨论“KPI/指标卡”。只有选中“KPI/指标卡”时才显示多指标模式和多TAB模式；其他组件不显示这两个配置项。

数据集配置区域的固定入口为：

```text
+ 添加数据集
```

属性面板不保留独立的“搜索”按钮；点击“+ 添加数据集”后，在数据源选择树内部提供搜索。

没有数据集时，只显示：

```text
暂未配置数据集输入
```

不得显示旧的“数据源”“指标”“维度”并列配置入口，也不得再增加独立的“脚本结果数据集输入”入口。

### 10.4 Python 预处理显示条件

| 条件 | 页面行为 |
| --- | --- |
| 未选择卡片 | 不显示卡片属性配置面板 |
| 已选择卡片 | 显示当前卡片的属性配置 |
| 0 个数据集 | 显示添加数据集入口和空态 |
| 1 个数据集 | 显示单数据集配置，Python 预处理为可选 |
| 2 个及以上数据集 | 显示 Python 预处理区域，并要求用户填写用户处理逻辑 |

“筛选器绑定”绑定到当前选中的“KPI/指标卡”，不再显示独立的“组件级时间筛选”。

Python 预处理区域通过“Python 预处理”和“筛选预览”表达。原型没有规定在“数据集配置”标题下增加解释性提示，因此不得增加以下类型的固定提示文案：



固定提示文案不得包含以下内容：

```text
先选择一个数据集；添加第二个数据集后，可配置 Python 预处理。
```

### 10.5 禁止新增的实现暴露

除非本原型文档后续明确增加，否则实现不得自行增加以下内容：

- 为解释内部状态而增加的说明文字；
- 目标组件或结果绑定组件选择器；
- 与当前卡片无关的全局数据集配置入口；
- 重复表达同一能力的并列入口；
- 未在本原型定义的额外配置步骤；
- 将历史 `dataSource`、`tabs[].dataSource` 或兼容字段直接作为新页面配置项展示。

历史配置只用于读取和渲染兼容；新建或编辑卡片必须遵循本节定义的新入口和当前卡片隐式绑定规则。

## 十一、卡片属性配置布局规范

本节规定卡片属性配置页面中各区域、按钮和组件的相对位置、排列顺序、滚动关系及状态变化。功能描述和布局描述必须同时满足；未在本节定义的控件不得自行添加。

### 11.1 页面整体布局

卡片属性配置页面采用“左侧画布 + 右侧属性面板”的布局：

```text
┌──────────────────────────────────────────────────────────┐
│ 顶部工具栏                                               │
├───────────────────────────────────────┬──────────────────┤
│                                       │ 属性配置         │
│                                       ├──────────────────┤
│             仪表盘画布                │ 可滚动配置内容   │
│                                       │                  │
│             当前卡片                  │                  │
│                                       │                  │
└───────────────────────────────────────┴──────────────────┘
```

布局规则：

| 区域 | 位置 | 规则 |
| --- | --- | --- |
| 仪表盘画布 | 左侧 | 占用剩余宽度，可滚动 |
| 属性配置面板 | 右侧 | 固定在右侧，宽度保持稳定 |
| 属性配置标题栏 | 面板顶部 | 固定显示，不随内容滚动 |
| 配置内容 | 标题栏下方 | 独立纵向滚动 |
| 当前卡片 | 画布区域内 | 被选中时显示选中边框 |

属性面板不得覆盖画布，也不得因为内容较多把整个页面撑开；只有属性面板内容区域滚动。

### 11.2 属性面板内部顺序

属性面板必须按以下顺序排列：

```text
┌────────────────────────────────────────────────┐
│ 属性配置                                       » │  ← 固定标题栏
├────────────────────────────────────────────────┤
│ 组件标题 [ KPI/指标卡              ]              │
│ 多指标模式                               开关按钮 │
│ 多TAB模式                               开关按钮 │
│ 添加数据集                                      │
│ 筛选器绑定                                      │
│ Python 预处理                    [筛选预览]     │
└────────────────────────────────────────────────┘
```

本节讨论对象为“KPI/指标卡”，因此多指标模式和多TAB模式必须显示。页面不显示“展示类型”和“组件级时间筛选”。

### 11.3 数据集添加入口位置

数据集添加入口只保留一个：

- 0 个数据集时，放在“数据集配置”标题行右侧；
- 已有 1 个或多个数据集时，移动到数据集表单列表底部；
- 不在标题行和列表底部同时显示两个添加入口；
- 搜索框只存在于“添加数据集”打开的数据源选择树中。

数据源配置采用自动进入下一步的方式：用户停止输入或选择 3 秒后，系统自动生成或刷新数据集表单；不提供额外的“确认进入下一步”按钮。配置错误时不自动进入下一步，并保留当前配置供用户修改。

### 11.4 数据集卡片布局

每个数据集使用一张独立表单，表单内部按以下顺序排列：

```text
┌────────────────────────────────────────┐
│ 数据源：接口                             │
│ 数据集别名：[table4]                     │
│ [字段名称] [筛选预览] [移除]              │
└────────────────────────────────────────┘
```

布局规则：

- 数据源显示在卡片标题行，右侧显示实际数据源的类型
- 数据集别名位于数据源信息下方；
- 字段名称、筛选预览、移除属于同一操作行；
- 移除操作位于卡片右下角；
- 多张表单按添加顺序纵向排列；
- 每张表单只能操作自身数据，不得出现跨表单操作按钮。

### 11.5 数据源配置弹窗布局

点击 JDBC、Aloudata、接口或文件来源后，打开对应配置弹窗。弹窗统一采用以下结构：

```text
┌────────────────────────────────┐
│ 配置当前数据集              ×  │
├────────────────────────────────┤
│ 配置表单区域                   │
│                                │
├────────────────────────────────┤
│ [取消] [筛选预览] [确定]       │
└────────────────────────────────┘
```

布局规则：

- 标题栏固定在顶部；
- 表单区域纵向排列并可独立滚动；
- 操作按钮固定在底部；
- “取消”位于左侧，“筛选预览”位于中间，“确定”位于右侧；
- 页面背景不滚动；
- 用户停止输入或选择 3 秒后，自动生成或刷新数据集表单；
- 配置不完整或校验失败时，不自动进入下一步；
- 如数据集表单已生成，用户修改配置后停止操作 3 秒，重新生成数据集表单。

### 11.6 Python 预处理区域布局

Python 预处理区域位于所有数据集表单和筛选器绑定之后：

```text
Python 预处理                         [筛选预览]

系统生成区域（只读）
┌──────────────────────────────┐
│ 输入数据集和筛选器绑定        │
└──────────────────────────────┘

用户处理区域（可编辑）
┌──────────────────────────────┐
│ Join、合并、计算和业务逻辑    │
└──────────────────────────────┘

                              [移除 Python 脚本]
```

规则：

- 一个数据集时，Python 预处理为可选；
- 两个及以上数据集时，Python 预处理区域显示，用户处理区域为必填；
- 系统生成区域在上，用户处理区域在下；
- 系统区域只读，重新生成不得覆盖用户处理区域；
- “筛选预览”先要求用户输入实际筛选条件值，再预览当前 KPI/指标卡的最终结果；
- “移除 Python 脚本”只移除当前卡片的用户处理脚本，不删除输入数据集；
- 不显示“当前目标组件”或“结果绑定组件”。

### 11.7 布局描述字段

每一个新增控件都必须在原型文档中说明：

| 字段 | 示例 |
| --- | --- |
| 所属区域 | 数据集配置 |
| 显示顺序 | 数据集标题之后、数据集表单之前 |
| 水平位置 | 左侧 / 右侧 / 充满宽度 |
| 垂直关系 | 与哪个控件同一行或上下排列 |
| 宽度 | 固定宽度 / 自适应 / 充满父容器 |
| 滚动关系 | 页面滚动 / 面板滚动 / 弹窗滚动 |
| 显示条件 | 0 个数据集、1 个数据集、2 个数据集 |
| 操作范围 | 当前 KPI/指标卡 / 当前数据集 / 全部数据集 |
| 禁止项 | 不得出现哪些额外控件 |
```

### 11.8 视觉验收状态

实现完成后，必须对以下状态进行视觉验收：

1. 空卡片；
2. 一个数据集；
3. 两个数据集；
4. 打开数据源选择器；
5. 打开 JDBC SQL 配置弹窗；
6. 打开字段映射弹窗；
7. 打开输入筛选弹窗；
8. 打开 Python 预处理区域；
9. 打开最终结果的“筛选预览”。

每个状态都必须检查：

- 控件顺序；
- 左右对齐；
- 面板宽度；
- 面板是否独立滚动；
- 按钮是否位于规定区域；
- 弹窗底部按钮顺序；
- 是否出现原型未定义的控件或文案。

视觉截图用于辅助核对，最终验收以本节的布局表、线框和状态规则为准。

## 十二、本轮需求冻结决策

以下规则为本轮“KPI/指标卡”属性配置的最终约定，后续设计、开发和测试以此为准：

1. 属性面板顺序为：组件标题 → 多指标模式 → 多TAB模式 → 添加数据集 → 筛选器绑定 → Python。
2. 多指标模式和多TAB模式只有在选中“KPI/指标卡”时显示；本轮不显示“展示类型”。
3. 不保留属性面板独立的搜索按钮；搜索只放在“添加数据集”打开的数据源选择树中。
4. 删除“组件级时间筛选”；筛选器绑定直接绑定当前选中的“KPI/指标卡”。
5. 数据源配置没有额外的“确认进入下一步”按钮；用户停止输入或选择 3 秒后自动生成或刷新数据集表单。
6. 数据集表单生成后，用户修改配置并停止操作 3 秒，系统重新生成表单；配置错误时不自动进入下一步。
7. JDBC 只允许 `SELECT` / `WITH`，不强制 SQL 包含 `WHERE`；所有查询参数使用绑定方式。
8. Aloudata 的“指标&维度”和“指标视图”均不提供额外确认按钮，选择或修改停止 3 秒后自动进入数据集表单。
9. 所有预览操作统一使用“筛选预览”按钮；执行前先由用户输入本次实际筛选条件值。
10. 一个数据集时 Python 预处理可选；两个及以上数据集时 Python 用户处理区域必填。
11. 本轮 Python 编辑器只支持 Python，不扩展 SQL 或 JavaScript 编辑模式。
12. Python 系统生成区域只读；重新生成系统区域不得覆盖用户处理区域。
13. 最终结果不是新的输入数据集；最终结果操作为“字段名称”“筛选预览”“移除 Python 脚本”。
14. 预览反馈必须提供“数据预览、字段结构、执行信息、处理日志”四个 Tab。
15. 预览失败、超时或取消时保留已有配置和上一次成功结果，不删除数据集；提供重试能力。
16. 接口配置确认后保存受控接口定义引用，敏感认证信息只引用凭据，不写入页面配置或日志。
17. 文件先上传到临时对象存储，再进行识别和预览；确认后只保存对象引用，不把文件内容写入仪表盘配置。
18. 输入筛选第一阶段支持 `=`、`!=`、`contains`、`in`、`between`、`is null`、`is not null` 和“最近 N 天”；多个条件默认使用 AND。
19. 同一真实数据集允许被当前 KPI/指标卡重复添加，但每个输入必须使用唯一别名，并拥有独立筛选和字段映射配置。
20. 点击确定只更新当前 KPI/指标卡草稿；点击仪表盘保存时才写入 Dashboard Schema，其他卡片配置不得被修改。
21. 历史 `dataSource` 和 `tabs[].dataSource` 只做读取和渲染兼容；新建或首次编辑保存时使用新的组件级数据集配置。
22. 「字段名称」弹窗的字段行由数据集 schema 自动生成，不提供“添加字段映射”手工新增入口；字段名与字段描述只读，仅“目标名称”可编辑（默认取显示名，无显示名时取源字段名），目标名称需非空且不重复。
23. 字段结构在数据集配置确定后自动预取，打开弹窗时缓存缺失则兜底实时拉取；重新拉取按字段名增量合并，用户改过的目标名称保留。
24. 字段重命名当前只作用于前端展示与配置层，后端尚未消费 `datasetInputs[].fieldMappings` 做投影重命名；凡真正下推到数据源的查询条件，必须用“目标名称”反解出的源字段名提交。
