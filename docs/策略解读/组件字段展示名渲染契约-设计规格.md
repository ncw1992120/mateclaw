# 仪表盘组件字段展示名渲染契约

## 状态

待用户审阅。本文经确认后进入实施计划与代码修改。

## 背景与目标

仪表盘字段配置已有展示名注册表，但查询结果进入组件数据后，表格列名、图表系列/图例/提示文案等部分路径仍保留技术字段名。目标是让所有面向用户的数据字段文案优先使用展示名，同时维持技术字段名作为查询、排序、筛选、脚本和数据绑定的稳定标识。

本规格覆盖洞察仪表盘编辑器预览、仪表盘预览及 AI 报告生成链路。筛选器、时间筛选器和组合卡片本身不展示字段名/展示名，继续按各自配置展示。组件标题不属于数据字段标签，不在本规格改动。

## 当前代码证据

- `mateclaw-dataagent-ui/src/utils/field-mapping.ts` 提供字段注册表标签解析；持久化映射位于 `datasetInputs[].fieldMappings`，`source` 是技术字段名，`target` 是展示名。
- `datasetInputs[].queryConfig.displayFields[].title` 另存查询字段标题；该标题当前可能与注册表标签不一致，构成重复来源。
- `src/utils/dataset-result.ts` 将行数据转换为组件数据时，表格列和部分图表字段仍使用原始 key。
- `src/utils/script-result.ts` 的脚本结果列有 `title` 元数据，但表格/图表适配路径未普遍保留或显示它。
- `InsightComponentData` 是编辑器与预览组件通用的数据承载类型；`DataTableWidget.vue`、`ChartWidget.vue`、`KpiCardWidget.vue`、`AiAnalysisWidget.vue` 分别负责主要可视化呈现。
- `DataAgentInsightDashboardController` 的 `POST /{id}/report` 无请求体；`InsightReportServiceImpl` 通过 `dataBindService.previewData(dashboardId)` 获取数据并构造 LLM prompt。AI 生成结果会写入所有 `aiAnalysis` 组件并保存 HTML 报告。

## 设计决定

### 1. 字段标签权威来源

`datasetInputs[].fieldMappings` 对应的 `target` 是数据集字段唯一权威展示名。`queryConfig.displayFields[].title` 用于查询字段选择与查询配置界面；保存查询配置时，其标题必须同步到相同字段的注册表标签，组件呈现不可另行以查询配置标题覆盖注册表。

旧数据、空标签或 `target === source` 时，展示回退为原始技术字段名。字段注册表没有记录的脚本派生列，使用 `ScriptResultColumn.title`（若非空）；否则回退列 key。这样既统一已登记数据集字段，也保留派生字段显式标题。

### 2. 运行时数据契约

组件数据适配后，技术字段 key、查询结果结构、筛选条件和排序参数保持不变；另提供字段 key 到展示标签的元数据，供渲染层查找。标签解析遵循：注册表展示名 → 未登记的脚本列 title → 技术字段 key。不得将展示名写回结果行、表达式、查询、筛选或排序字段。

所有数据进入画布预览、属性面板预览、仪表盘预览及结果集恢复路径时，使用同一标签解析规则，避免同一组件在不同页面显示不一致。

### 3. 组件覆盖

- 表格：列头使用展示名，列排序仍传技术字段 key；列宽、横向/纵向滚动、分页、行值和导出数据结构不因标签变化。
- 图表：系列名称、图例、坐标轴名称、tooltip 字段名使用展示名；option 中匹配字段的 `name`/`seriesName`/维度显示文案可转换，数据编码、维度 key、指标 key、映射字段与查询字段仍使用技术字段名。组件标题不改。
- 指标卡：字段名称使用注册表展示名；值、单位、比较逻辑与数值格式不变。不得以组件级缓存名称覆盖注册表；独立的组件标题仍按原设置显示。
- AI 分析：新生成报告的 prompt 上下文使用展示名描述数据字段与图表系列；报告中的可读文案自然采用展示名。已有历史报告不自动重写。组件自身标题仍按原设置显示。
- 筛选器、时间筛选器、组合卡片：不处理字段展示名，保持现状。

### 4. AI 报告链路边界

保持现有报告 API 请求形态及数据持久化行为。服务端生成 prompt 时，依据仪表盘 schema 中各数据集 `fieldMappings` 构建标签映射，并应用于提供给模型的预览字段/图表上下文；底层查询字段和真实数据不改名。流式和同步报告共享同一 prompt 构造规则。

AI 生成的自由文本无法可靠地反向替换既有技术字段名，因此仅保证生成上下文和新报告输出偏好展示名，不承诺对历史内容或用户自行输入的正文做全局替换。

## 考虑过的方案

1. **仅在各 widget 内各自查 schema**：修改点分散，属性预览、恢复数据和 AI 上下文容易漏路径；不采用。
2. **适配结果时统一附加标签元数据，渲染层按组件类型消费**：查询键稳定，多个适配入口可以复用统一解析规则；采用。服务端 AI 报告单独在 prompt 构造阶段复用相同映射规则。
3. **把展示名替换成结果字段 key**：会破坏排序、查询、脚本字段引用和数据绑定；不采用。

## 验收标准

1. 配置了展示名的数据集字段，在表格、图表（系列/图例/坐标轴/tooltip）和指标卡中均显示展示名。
2. 未配置展示名或读取旧 schema 时回退技术字段名；脚本派生字段使用非空 `title`，没有 title 时回退字段 key。
3. 更改一个字段展示名并保存后，查询预览、编辑器画布和独立仪表盘预览一致更新。
4. 表格列排序、查询筛选、图表数据映射和指标值不因显示标签改变而变化，相关交互仍按技术字段名工作。
5. AI 同步及流式报告 prompt 的字段上下文采用展示名；新生成报告遵循展示名，已保存旧报告不被迁移或重写。
6. 筛选器、时间筛选器、组合卡片及组件标题呈现保持原有逻辑。
7. 自动化验证覆盖标签解析、结果适配和 AI prompt 字段上下文；浏览器验收分别检查编辑器与预览的表格/图表/指标卡显示及排序交互。

## 实施边界

预计涉及 `mateclaw-dataagent-ui` 的字段映射、数据结果适配、通用组件数据类型、图表/表格/指标卡渲染、查询配置保存同步，以及 `mateclaw-dataagent` 的报告 prompt 上下文。提交前按实际调用链调整文件清单；不改查询执行契约、数据库结构、筛选器/时间筛选器/组合卡片配置格式。
