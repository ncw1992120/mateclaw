# 洞察-仪表盘：卡片数据链路与「结果集」交互方案（讨论稿）

> 状态：讨论稿，未定稿。代码未改动。
> 日期：2026-09-18
> 涉及模块：mateclaw-dataagent-ui（洞察编辑器 / 卡片属性配置）、mateclaw-dataagent（组件取数）

---

## 一、结论速览

用户的原始疑问是：**「数据集加了、筛选条件也填了、数据也过滤出来了，卡片为什么不显示数据？需要一个按钮吗？」**

结论：**不是操作问题，是链路缺了一环。**

- 现在能"配"、能"预览"，但缺"结果落地成卡片数据"这一环。
- 建议引入 **「结果集」作为一等公民**：一组 `schema + 行数 + 生成时间戳`，是卡片唯一的数据来源。
- 数据集配置、筛选条件、Python 脚本都只是"怎么产出结果集"的手段，不是卡片的数据。
- 需要一个动作，但它叫 **「生成 / 重新生成结果集」**，不叫「预览」。
- 该动作的自动性按成本分档：**无脚本自动跑，有脚本手动跑**。

## 二、现状：数据为什么到不了卡片

属性配置面板（`AttributePanel.vue:41-123`）把配置写进 `component.config.datasetPipeline`
（类型见 `types/index.ts:1386-1392`），结构为：

```
datasetPipeline = { datasetInputs[], scriptFilterBindings[], script, parameters, executionPolicy }
```

链路存在三处断点，任何一处都足以让卡片显示不出数据：

| # | 断点 | 位置 | 后果 |
|---|------|------|------|
| 1 | 新数据集只有前端草稿 id，`confirmDatasetDraft()`（把草稿提交后端换真实 `datasetId`）全仓从未被调用 | `useInsightBackend.ts:86-91` 定义了但无调用方；`useInsight.ts:1032-1049` 回退成 `ds-<时间戳>` | `datasetInputs[].datasetId` 不是真实数据集 id |
| 2 | 后端组件取数只读 `component.dataSource`，完全不读 `config.datasetPipeline` | `InsightDataBindServiceImpl.java:89-92` | 管道配置的卡片取数返回「组件未配置数据源」 |
| 3 | 编辑器自动取数的白名单条件是 `dataSource.datasourceId && dataSource.metrics.length` | `InsightDashboardEditorView.vue:898` | 管道配置的卡片被排除在自动预览之外 |

于是当前唯一能看到数据的地方是**「筛选预览」弹窗**，而且：

- 弹窗只在 `visible` 变 true 时才发请求（`PreviewDialog.vue:146-157`），关掉即丢；
- 点「筛选预览」实际上走了 `saveDashboard + executeComponent`（`useInsight.ts:1368-1401`），
  **一个叫"预览"的按钮产生了持久化副作用**，语义错误。

## 三、核心设计：把「结果集」显式化

### 3.1 概念定义

**结果集（Result Set）**：一次成功产出、可直接驱动卡片渲染的数据集合。

- 三个必备属性：`字段（schema）`、`行数（rowCount）`、`生成时间（generatedAt）`
- 唯一出口：卡片只能从结果集取数
- 唯一真源：**指标配置的候选字段 = 结果集的 schema**

### 3.2 与现有概念的关系

| 现有概念 | 归属 | 与结果集的关系 |
|---|---|---|
| 数据集（`datasetInputs[]`） | 输入 | 是产出结果集的原料，本身不是卡片数据 |
| 筛选条件（`filters`） | 输入加工 | 改变结果集的内容 |
| 筛选器绑定（`scriptFilterBindings`） | 输入参数 | 把仪表盘筛选器接到脚本入参上 |
| Python 脚本（`script`） | 输入加工 | 有脚本时，结果集 = 脚本的输出 |
| 结果集 | 产物 | 卡片唯一数据来源 |

## 四、结果集状态机

```
未配置 ──添加数据集──▶ 已过期 ──生成──▶ 生成中 ──成功──▶ 就绪
                        ▲                  │              │
                        │                  └──失败──▶ 失败 │
                        └────────配置变更───────────────┘
```

| 状态 | 进入条件 | 面板结果集节点 | 卡片 | 主按钮 |
|---|---|---|---|---|
| 未配置 | 数据集数量为 0 | 「尚未配置数据」 | 空态插画，点击打开面板 | + 添加数据集 |
| 已过期 | 数据集 / 筛选 / 脚本任一变更 | 「结果集已过期」+ 上次的行数与时间 | 沿用上次渲染 + 「数据已过期」角标 | 重新生成 |
| 生成中 | 生成动作启动 | 进度 / 实时日志 | 沿用上次渲染 + 转圈，不阻塞继续改配置 | 取消 |
| 就绪 | 生成成功 | 字段数 · 行数 · 生成时间 · 耗时 | 用结果集渲染 | 预览结果集 / 重新生成 |
| 失败 | 脚本抛错或数据源不可达 | 错误摘要 | 沿用上次渲染 + 红色角标（不清空卡片） | 重试 / 查看日志 |

### 4.1 自动 vs 手动：按成本分档

| 情况 | 取数方式 | 行为 |
|---|---|---|
| 无脚本（0-1 个数据集） | 同步、毫秒级 | **自动**：配置变更后防抖（约 800ms）自动生成；保留手动刷新按钮兜底 |
| 有脚本（1 或 N 个数据集） | 异步：Runner 提交任务 + 轮询（当前最长 20s） | **手动**：等用户点「生成结果集」 |

心智模型收敛为一句话，用户不需要学两套规则：

> **改完配置，结果集就旧了，刷新一下就新了 —— 只是没脚本时它自己会刷。**

### 4.2 为什么不建议"强制每次都必须预览一次"

场景 2 / 3 中，脚本输出确实需要用户过目（脚本可能有 bug）。但把"必须点一次确认"做成硬门槛，
在反复调脚本时会被点几十次，代价过高。

建议折中：**脚本成功后结果集自动就绪并渲染卡片，同时自动展开一次结果集预览面板，并在结果集上打「脚本输出」来源标签。**
给了"看一眼"的机会，但不阻塞。是否需要改成硬门槛见第七节决策点 A。

## 五、三种输入场景的统一

用户提出的三种情况，差异只在"结果集从哪来"，到了结果集之后完全一致。**不需要三套交互。**

| 场景 | 输入 | 加工 | 结果集来源 | 触发方式 |
|---|---|---|---|---|
| 1 | 1 个数据集 | 无脚本 | 数据集本身（直通） | 自动 |
| 2 | 1 个数据集 | Python | 脚本输出 | 手动 |
| 3 | N 个数据集 | Python（必填） | 脚本输出 | 手动 |

统一表达为一条管道：

```
[输入数据集] ──▶ [Python 处理（可选）] ──▶ [结果集] ──▶ 卡片
```

### 5.1 场景 3 的两个附带约束

- 多数据集时 `pythonRequired = datasets.length >= 2`（`useInsight.ts:258`），
  Python 用户处理区必填 —— 这部分现有逻辑可以直接复用。
- 脚本系统生成区按别名声明输入（`ds1 = inputs["ds1"]`，`useInsight.ts:176-195`），
  **改数据集别名会使脚本失效**。建议改别名时给出提示，或让系统区自动重写。

### 5.2 命名必须拆开

现在**两个不同层级的预览共用了「筛选预览」这个名字**：

- `DatasetCard.vue:32` → 看**单个输入数据集**的样子
- `AttributePanel.vue:85` → 看**最终输出**的样子

用户无法从字面区分。建议：

| 位置 | 现名 | 建议名 |
|---|---|---|
| 数据集卡片内 | 筛选预览 | **查看数据**（明确是看单个输入） |
| 管道末端结果集节点 | 筛选预览 | **预览结果集** |

## 六、属性面板改造

### 6.1 现状结构

`AttributePanel.vue` 是纵向 section 平铺，依次为：

1. 组件标题（`22-26`）
2. 多指标模式 / 多 TAB 模式（`29-38`，仅 KPI 卡）
3. 数据集配置（`41-60`）
4. 筛选器绑定（`62-78`）
5. Python 预处理（`80-111`）
6. 指标配置（`116-123`，仅 KPI 卡）

问题：用户看不出这些分区**怎么串成数据**。

### 6.2 建议结构：改为纵向数据管道

```
属性配置
─────────────────────────────
1  输入数据集                    [+ 添加]
   ┌─────────────────────────┐
   │ 指标视图 · 销售明细       │
   │ [sales] · 1,203 行       │
   │ 字段名称  查看数据  移除  │
   └─────────────────────────┘
              │
2  Python 处理（可选）      ● 已配置
   ┌─────────────────────────┐
   │ 用户处理区 6 行 · 输入 [sales]│
   │ 展开编辑  移除脚本        │
   └─────────────────────────┘
              │
3  结果集                     ● 就绪
   ┌─────────────────────────┐
   │ 12 个字段 · 486 行        │
   │ 16:32 生成 · 耗时 4.2s    │
   │ [预览结果集] [重新生成]   │
   └─────────────────────────┘
              │
4  指标配置  （候选字段取自结果集 schema）
─────────────────────────────
```

各节点状态点：灰=未配置，黄=已过期，蓝=生成中，绿=就绪，红=失败。

### 6.3 连带修的几处

- **指标配置的字段来源**：从"所有数据集字段并集"（`useInsight.ts:871-882`）改为"结果集 schema"；
  结果集未就绪时按钮禁用，并提示原因。
- **「筛选器绑定」的可见性**：它当前产出的是脚本入参（`scriptFilterBindings`），
  无脚本时应隐藏或明确说明不可用（待确认，见决策点 C）。
- **预览弹窗与卡片的关系**：建议预览成功后结果集直接成为当前结果集、卡片立即填充，
  弹窗退化为"结果集的详细视图"（数据 / 字段结构 / 执行信息 / 处理日志四个页签保留）。
- **编辑器画布的卡片**：显示最近一次就绪结果集的渲染结果；
  配置变更后打「数据已过期」角标，点击即刷新，而不是清空。

## 七、已确认的决策（2026-09-18）

| # | 决策 | 结论 |
|---|------|------|
| A | 脚本产出的结果填卡片前是否需人工确认 | **自动填充**。脚本成功即成为结果集并渲染卡片，同时自动展开一次结果集预览面板，并在结果集上打「脚本输出」来源标签 |
| B | 结果集是否持久化 | **持久化**。随仪表盘一起存，重开秒显上次结果；配置变更时打「已过期」角标提示刷新 |
| D | 面板结构 | **重构成纵向数据管道**。四节点串联，各带状态点 |

### C.（仍待确认）「筛选器绑定」在无脚本场景下是否有效？

当前它产出 `scriptFilterBindings`，按别名展开（`useInsight.ts:1051-1059`），
看起来是脚本级能力。无脚本场景（用户场景 1）下它该隐藏、还是应该有直通作用？需确认产品意图。

## 八、实现顺序建议

1. **打通后端取数**（断点 2、3）：让组件取数认识 `config.datasetPipeline`，或把结果集回写到组件可读的位置。
2. **接线数据集草稿提交**（断点 1）：明确 `confirmDatasetDraft` 的调用时机，让 `datasetInputs[].datasetId` 是真实 id。
3. **结果集持久化**（决策 B）：复用 `DashboardExecutionEntity.outputJson / outputRefJson`（`DashboardExecutionServiceImpl.java:208-219`），并补一个"按组件读当前结果集"的读取接口。
4. **前端结果集状态机**：实现五态 + 自动/手动分档（无脚本自动刷新，有脚本手动）。
5. **前端面板改造**（决策 D）：四节点纵向管道 + 节点状态点。
6. **指标配置字段源切换**：从"数据集字段并集"（`useInsight.ts:871-882`）改为"结果集 schema"，未就绪时禁用。
7. **命名拆分**：数据集卡片「筛选预览」→「查看数据」；管道末端 →「预览结果集」。
