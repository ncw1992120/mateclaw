# 洞察仪表盘 · KPI 指标卡片自动铺排实施计划

> 需求原文：`洞察 - 仪表盘 - 组件库 - 指标卡片，在用户配置数据进行应用后，这时指标个数已经是确定的，
> 应该默认就直接根据指标个数及画布中指标卡片大小，进行字体大小适配、排几行的行数适配，居中摆放`

状态：**已实施**（2026-10-09）

## 一、问题

KPI 指标卡片的指标块是像素级自由布局（`KpiMetricConfig.x/y/w/h`），但**默认排布不看卡片实际大小**：

- `buildKpiMetrics()` 给新指标写死 `defaultMetricLayout(index)` = 两列错落 `{ x: col*172, y: row*80, w: 160, h: 72 }`；
- 字号写死出厂值（展示名 14 / 指标值 28 / 单位 15 / 辅助说明 12）。

后果：卡片只有 300px 宽时两列默认排布直接溢出；卡片很大时指标挤在左上角、字号偏小；
行数与列数永远不会随「指标个数 + 卡片尺寸」变化。

## 二、口径（本方案定义）

**未被动过手的卡片默认自动铺排**；用户一旦手工调整即转为手动布局，完全按保存的坐标渲染。

| 维度 | 规则 |
| --- | --- |
| 触发 | 卡片的**全部可见指标**都仍是「机器默认排布」（当前默认公式或旧版 284×88/步距 296×96 公式），且已量到可用区尺寸 |
| 输入 | 可见指标个数 `count`、`.kpi-metric-group` 的内容区尺寸 `areaW × areaH` |
| 列数/行数 | 枚举 `columns = 1..count`，`rows = ceil(count / columns)`；淘汰单元格小于舒适档的方案；在剩下的方案里比优劣 |
| 单元格尺寸 | 等分槽位 `slotW/slotH`，**上限 280×96**（只制约拉伸，不制约收缩），超过上限的部分留给居中 |
| 居中 | 整块尺寸 `columns*cellW + (columns-1)*gapX` 与可用区的差值平分到两侧（水平 + 垂直） |
| 铺排顺序 | 列优先（先左到右，再换行），与「结果集字段顺序」一致 |
| 字号 | **对全部指标生效**：`出厂字号 × 适配系数`，取整，下限 9px；系数按「该指标实际占用的盒子」计算 = `min(boxW/160, boxH/72)` 夹到 **[0.62, 1.5]**（自动铺排时盒子即单元格；手动布局时盒子是用户固定尺寸） |
| 间距/行距 | **随同一系数自适应**：`metricStyle` 给每个指标块注入 CSS 变量 `--kpi-metric-scale`（= 字号适配系数），行间隙 `calc(2px×系数)`、值-单位间隙 `calc(3px×系数)`、内边距与圆角 `calc(基准×系数)`；文字 `line-height: 1.2` 为无单位值，本就随字号等比缩放 |
| 字号逃生口 | **用户在样式弹窗显式改过字号的字段不参与适配**（判定依据：字号 ≠ 出厂值） |
| 块内对齐 | 指标块内容水平 + 垂直居中（`text-align: center` + `align-items: center`），**对全部指标生效**，自动与手动布局观感一致 |
| 放弃条件 | 连可用下限（64×44）都排不下时返回 `null`，回落持久化坐标；可用区尺寸未知（0/undefined）同样不接管 |

### 补充规则（2026-10-10 追加）：破损布局自动修复 + 小卡片尽力收进容器

> 起因：真机验证发现「策略解读」老看板的指标分组卡片实际效果不理想——
> ① 两张卡的持久化盒子互相重叠（x=97 而邻居宽 120、行位 69/80 参差），被当作手工布局原样保留；
> ② 一张 7 指标卡的机器默认盒子排到 y=312 而容器只有 141px 高，自动铺排因「排不下就放弃」
>    （floor 兜底返回 null）不接管，字号也不适配，内容大幅溢出卡片。

两条新规则：

1. **破损布局自动修复**（`hasMetricLayoutConflict`）：持久化盒子**互相重叠**、**越出可用区**（含负坐标）
   或坐标非有限数 → 视为「破损」，自动铺排接管重排。破损不可能是用户有意的排版
   （多为历史版本默认公式 / 模板遗留）。用户拖出的合法布局（相接不重叠、都在界内）不受影响。
   **本会话内被拖动 / 缩放过的卡片**（`sessionAdjustedIds`）不再自动重排，尊重当次操作结果。
2. **小卡片不再放弃**（`planKpiAutoLayout` 尽力而为）：删除「可用下限（64×44）达不到即返回 null」的兜底，
   面积有效时**总有解**——连舒适档（88×48）都排不下也取全局最优方案收进容器并居中，
   字号压到下限 9px。返回 null 仅表示可用区尺寸未知（首帧 / jsdom）。
   放弃只会让持久化坐标原样溢出卡片，比「字号收紧到下限」观感差得多。

效果（真机复验）：重叠的 2×2 卡重排为均匀网格（102×64 单元格、值 18px / 名 9px）；
7 指标小卡收进 3×3 网格（64×39 单元格、值 17px / 名 9px），不再溢出。

遗留观察（非布局问题）：该看板这些指标卡的 `datasetId` 为空、编辑态 `componentData` 缺失，
所有指标值显示 `--`；且投影进来的字段多为维度列（统计日期 / 计划 id 等），
是否应默认成为 KPI 指标、示例数据如何回填，属数据链路问题，另行处理。

### 补充规则（2026-10-09 追加）：手工摆过的老看板指标也居中 + 自适应字号

> 需求原文：`老看板里被手工摆放过的指标 也要保持居中并 自适应字体大小`

「自动铺排」分两层，需区分对待：

1. **盒子坐标（列数 / 行数 / 摆放位置）**：只对「从未被手工调整过」的卡片自动计算。
   用户拖动 / 缩放任一指标 → 整卡转手动布局，盒子坐标完全按保存值渲染，**不**重新排。
2. **居中 + 字号自适应**：对**全部**指标生效，与是否自动排布无关。
   手动布局的指标保留用户摆好的盒子位置（`renderedBox` 回退到持久化 `x/y/w/h`），
   但盒子内仍居中、字号仍按盒子大小自适应（新增 `metricBoxScale(box.w, box.h)` 驱动）。

效果：一张老看板里被手工摆过的卡片，指标块不会重新排布（尊重用户摆位），
但每个指标块内文字居中、字号随盒子放大 / 缩小 —— 不会出现「大盒子小字」或「小盒子溢出」的观感断层。
「字号逃生口」依然只对「用户显式改过字号的字段」生效。

### 方案优劣比较（`planKpiAutoLayout` 内的比较器）

1. **字号适配系数越大越好** —— 指标值尽量大，这是 KPI 卡片的首要诉求；
2. 同分时，**单元格长宽比更接近基准比例 160/72** —— 避免出现又扁又长或又瘦又高的指标位；
3. 再同分时，**行数更少、列数更少** —— 保证结果稳定可预期。

### 常量（`src/utils/kpi-metrics.ts`）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `KPI_AUTO_REF_CELL` | 160×72 | 基准单元格：出厂字号在此尺寸下排版自然 |
| `KPI_AUTO_GAP` | 12×12 | 单元格间距（与 `defaultMetricLayout` 留白口径一致） |
| `KPI_AUTO_MAX_CELL` | 280×96 | 舒适上限，超出部分用于居中 |
| `KPI_AUTO_SCALE_MIN/MAX` | 0.62 / 1.5 | 字号适配系数区间 |
| `KPI_AUTO_MIN_FONT` | 9 | 适配后的最小字号 |
| `KPI_LAYOUT_CONFLICT_EPSILON` | 0.5 | 破损判定容差：盒子边缘相接不算重叠 |

## 三、为什么不持久化自动铺排结果

自动铺排结果**只用于渲染、不写回 schema**：

- 同一张看板在编辑态（24 栅格）与预览态（自适应宽度、`previewFillWidth`）的卡片像素宽度不同，
  把编辑态算出的坐标写死会让预览态错位；
- 卡片尺寸变化（拖画布手柄、窗口缩放、画布缩放）都要重排，写回会持续制造 schema 变更与脏标记。

因此渲染尺寸由 `ResizeObserver` 实测 `.kpi-metric-group` 内容区驱动，纯函数按「个数 + 尺寸」算出。

### 拖动 / 缩放时的固化（避免视觉跳变）

自动铺排只接管「未被手工调整过」的指标；用户动了其中一个，整卡就转手动布局。
若不在按下的瞬间把当前自动铺排结果**固化**成持久化坐标，松手后其余指标会立刻退回旧默认坐标、
画面会跳一下。所以 `onMetricMouseDown` / `onMetricResizeDown` 的第一步就是 `materializeAutoLayout()`，
再以固化后的坐标作为拖动起点 —— 固化后 `autoLayout` 自然变 `false`（坐标不再是机器默认值）。

### 隐藏指标的下标

机器默认布局是按**配置里的原始下标**生成的，而铺排只针对可见指标。
所以「是否机器布局」的判定用原始下标（`visibleSourceIndexes`），铺排位置用可见序号 ——
否则「隐藏第一个指标」会被误判成手工布局，自动铺排整个失效。

## 六、已知边界

- 单元格过窄时（例如 300px 宽卡片放 4 个带 2 字单位的指标）长数值仍会被省略号截断 ——
  这是卡片尺寸不足的物理限制，自动铺排已把字号压到刚好放得下；要彻底解决需按文本实测宽度逐格收敛字号
  （会让同行指标字号不一致，本轮明确不做）。
- 「被手工调整过 = 全卡转手动」是**卡片级**粒度，不区分单个指标：动一个就全卡固定，
  换来的是行为可预期（不会出现「一半自动一半手动」的错位）。
