## 一、图标（Icons）

### 1. 文本字符充当图标，视觉不统一 ⭐ 优先处理
- `KpiCardWidget.vue:68`：「配置字段样式」按钮内容是冒号 `:` —— 看起来像 `⋮`（MoreFilled）的笔误，用户无法理解其含义。
- 页签删除 `✕`（`CombinationCardWidget.vue:36,64`）、新增页签 `+`（`:38`）均为裸文本字符。
- **建议**：统一改用 `@element-plus/icons-vue`（项目已引入：`MoreFilled` / `Close` / `Plus` / `Setting`），或沉淀一套内联 SVG 功能图标。文字字符在不同字体下的基线与字重不可控，是图标体系中最容易「露馅」的地方。
- 同时 `title="配置字段样式"` 等提示未走 i18n，而同文件的页签用了 `t('insight.…')`，两套用法混在一起。

### 2. 空状态使用 emoji
- `CombinationCardWidget.vue:45`：空状态图标是 `🗂️`。emoji 跨平台渲染差异大（Windows 无彩色 emoji 字体时退化为黑白轮廓），与界面里其余 Element Plus 图标风格割裂。
- **建议**：改用线性图标（如 `Files` / `Box`），并把「图标 + 文案 + 可选操作按钮」沉淀成共享 `EmptyState.vue`，组合卡片、KPI 空态（`kpi-placeholder` 目前是纯文本）共用，顺便可以加一个「添加组件」按钮式引导替代纯文案。

## 二、交互（Interaction）

### 3. KPI 指标拖拽在 mouseup 回读 DOM style，会丢最后几像素位移 ⭐ 有实感 bug
- `KpiCardWidget.vue:329-341`（`onMetricMouseUp`）：`cancelAnimationFrame` 后直接 `parseInt(el.style.left)` 提交落点。最后一次 mousemove 如果没赶上下一个 rAF 帧就发生了 mouseup，末帧位移会被丢弃——快速甩动时指标会「差一点没到位」。
- 这正是组合卡片已经踩过并总结过的坑（过程计算与落点提交必须是同一个纯函数 `computeMove`/`computeResize`），但 KPI 指标分组是另一份独立实现，坑又重现了。
- **建议**：把拖动/缩放抽成共享 composable（如 `useFreeDragResize.ts`），mousemove 只记 `lastEvent`，落点在 mouseup 时用纯函数从 `lastEvent` 计算，不回读 DOM。组合卡片与 KPI 卡共用一份，顺带消除两份 ~120 行的近似重复逻辑。

### 4. 全局 `document.querySelector` 查找拖拽目标
- `KpiCardWidget.vue:303,367`：`document.querySelector('[data-metric="…"]')` 是全文档查找，多张 KPI 卡配了同名字段时会抓错元素。
- **建议**：mousedown 事件里用 `e.currentTarget`，缩放手柄用 `$el.closest('.kpi-metric')`，零成本消除隐患。

### 5. 拖拽占位符全透明 = 丢掉了「落点反馈」
- `a4a7ca04` 把 `--vgl-placeholder-bg: transparent; --vgl-placeholder-opacity: 0` 完全抹掉了 grid-layout-plus 的拖拽占位。粉红残影没了，但「松手后会落在哪里」的预期也没了。
- **建议**：不必全透明，改成品牌色低透明即可，既干净又有落点预期：
  ```css
  --vgl-placeholder-bg: var(--db-accent);
  --vgl-placeholder-opacity: 0.08;
  ```
  另可补一条 `--vgl-placeholder-radius` 与卡片圆角一致。

### 6. 组合卡片页签的可访问性与边界情况
- KPI 卡页签做了完整的 `role="tablist"` + 方向键/Home/End 键盘导航（`KpiCardWidget.vue:25-40,167-186`，做得很好），但组合卡片页签（`CombinationCardWidget.vue:18-39`）是裸 `div`，无 role、无键盘支持。建议把 KPI 的键盘导航抽成 `useTabNavigation` 两边复用。
- 已知未修：页签栏 `v-if="cfg.tabs.length"`，无页签时「+」不渲染，从零建不了第一个页签。
- 双击重命名（`dblclick`）完全没有视觉提示，用户发现不了；建议 hover 时标题旁淡入一个铅笔小图标作为 affordance。
- 删除页签/子组件都是单击 `✕` 立即删除且不可恢复；建议 `ElMessageBox.confirm` 或至少 `ElMessage` + 撤销操作，防误删（尤其删除页签会连带其下子组件配置）。

### 7. 触屏与悬停依赖
- 样式按钮（`.kpi-metric-style-btn`）和八向手柄都靠 `:hover` 显示（opacity 0→1）。编辑态下选中即常显更稳；且触屏设备没有 hover，功能会不可达。
- 八向手柄视觉 12px，触达热区偏小；建议用伪元素把热区扩到 ~20px（视觉不变）。

## 三、样式（Styles）

### 8. 涨跌色语义与国内金融惯例相反 ⭐ 需产品确认
- `dashboard-design.css:42`：`--db-positive: #22c55e`（绿），`.kpi-chg.up` 用它 → **涨显示绿色**。国内金融/经营看板惯例是「涨红跌绿」。
- **建议**：把语义 token 拆开——`--db-up` / `--db-down`（语义为方向）与 `--db-positive` / `--db-danger`（语义为好坏）分离，按产品面向的受众配置映射。这属于一处 token 调整即可全局生效的事，越早拆越便宜。

### 9. 取色器预设色板两处定义、不成体系
- `PropertyPanel.vue`：8 个「暖色背景」（奶油白→浅驼）；`MetricStyleDialog.vue`：12 个「暖色文字色」（红→暖棕）。两份硬编码数组、两种用途，没有共享来源，后续改色板要改两处，且和 `dashboard-design.css` 的 token 无关联。
- **建议**：收敛到一个 `src/utils/color-presets.ts`（或并入 design token 文件），按用途分组导出：
  ```ts
  export const CARD_BG_PRESETS = [...]   // 卡片/容器背景
  export const TEXT_COLOR_PRESETS = [...] // 指标值/文本
  export const CHART_SERIES_PRESETS = [...] // 图表系列色（后续图表卡片可复用）
  ```
  同时补一版暗色主题校验（浅杏色背景块在暗色面板上的预览效果目前没有验证过）。

### 10. 行内样式 + `!important` 覆盖
- `KpiCardWidget.vue:13`：`style="width: 200px"`，移动端又用 `!important` 强行改回 100%（`:787-789`）。改成 `:deep(.el-date-editor) { width: 200px }` 的类规则即可删掉行内样式和 `!important`。

### 11. 数字排版
- `.kpi-value` 已用 `font-variant-numeric: tabular-nums`（好），但 `.kpi-metric-value`（指标分组模式）没加；拖拽/缩放过程中数字宽度抖动会更明显。建议补齐同一声明。

### 12. 调试脚本落在组件根目录
- `mateclaw-dataagent-ui/` 根下散落 `_debug_real_editor.mjs`、`_repro_child_drag.mjs` 等 6 个复现脚本（untracked）。建议移入 `dev-support/local-simulation/scripts/` 或加入 `.gitignore`，避免误提交。

### 13. 值得固化为规范的部分（保持住）
- KPI 页签的 WAI-ARIA 键盘导航、`tabular-nums` 数字排版、组合卡片「过程 rAF + 纯函数落点」的拖拽策略、设计 token 化的间距/圆角/颜色体系——这些是本次提交里的亮点，建议沉淀进 `insight/DESIGN_SPEC.md` 作为该模块的硬约束。
