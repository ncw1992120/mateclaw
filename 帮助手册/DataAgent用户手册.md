# MateClaw DataAgent 用户手册

> **DataAgent 是一个"用大白话问数据"的工具。**
> 你不用会写 SQL、不用记字段名，像跟同事聊天一样把问题说出来，它就会把数据查出来、画成图，甚至自动写一份分析报告。
>
> **这本手册怎么读：**
> - 如果你只想**赶紧开始问数**：把 **第一章** 和 **第二章** 看完就够了（大约 10 分钟）。
> - 如果你要**做看板、发报告**：再加 **第五章**、**第六章**。
> - **第八章是管理员看的**，业务用户可以直接跳过。
> - 遇到报错，直接翻 **2.6 报错速查表**，比通读全文快。

## 一、它是什么？5 分钟看懂

### 1.1 它能帮你干什么

| 你想干的事 | 你就这么问 | 你会得到 |
|-----------|-----------|---------|
| 要一个数 | "上个月华东区销售额是多少？" | 一段结论文字 + 一张图 |
| 做对比 | "各产品线本季度销售额对比" | 对比柱状图 + 谁高谁低 |
| 看走势 | "近一年每月用户数变化趋势" | 折线图 + 趋势判断 |
| 看涨跌 | "本月销售额环比增长多少？" | 涨跌幅数字 + 原因拆解 |
| 做看板 | "帮我做一个销售大屏" | 一个可点击、可筛选的仪表盘 |
| 写报告 | "给这个月的销售出份分析报告" | 一份带图表和结论的分析文档 |
| 连续追问 | 接着上一句问"那 3 月呢？" | 它记得上文，不用重复条件 |

### 1.2 为什么它答得准

它**不是**让大模型直接"猜"一个答案，而是**一步一步查证过的**：

1. 你嘴里说的业务词（比如"营收"），它先去**业务词典**里查清楚：这个词对应数据库里哪个字段、怎么算的；
2. 再找到**哪张表、哪个指标**能回答你这个问题；
3. 如果这个词有两种口径，它**会反过来问你**要哪一种，不会自己乱选；
4. 最后算完，用一段话把结论讲给你听，并自动配一张合适的图。

> 一句话：**你负责说清楚"要什么"，它负责搞明白"到底查哪个数、怎么算、怎么画"**。中间的坑——同义词、口径不一致、多表关联——都由它处理。

### 1.3 登录后你会看到什么

顶部有 5 个入口，从左到右：

| 顶部入口 | 是干什么的 | 业务用户会用到吗 |
|---------|-----------|----------------|
| **问数** | 主界面，直接提问 | ✅ 用得最多 |
| **洞察** | 你的仪表盘（看板）列表 | ✅ 做看板时用 |
| **报告** | 查看 / 发布 AI 分析报告 | ✅ 发报告时用 |
| **配置** | 管理员维护系统（数据源、模型等） | ⚠️ 只有绑查询账号时会进 |
| **帮助** | 帮助文档 | 偶尔 |

右上角还有三样东西：

- **工作空间下拉框**：在不同团队/项目之间切换（详见 3.3）；
- **主题切换**：深色 / 浅色；
- **你的头像**：目前只有"退出登录"。

### 1.4 先认几个词（看懂了后面就不费劲）

手册里会出现一些"行话"，这里一次性说清楚：

| 你看到的词 | 说人话就是 |
|-----------|-----------|
| **智能体 / Agent** | 你对话的那个"助理"。不同助理擅长的事不一样 |
| **数据源** | 系统连着的一个数据库（或指标平台）。数就是从这儿来的 |
| **查询账号** | **你自己的**数据库账号。系统用你本人的账号去查数，所以你能看到的数据和别人不一样 |
| **指标** | 你要的那个数，比如"销售额""订单量""AUM" |
| **维度** | 拆分的角度，比如"按地区""按产品""按月份" |
| **业务词典** | 一本"黑话翻译表"，把你公司的习惯叫法翻译成数据库里的字段名 |
| **技能** | 助理会的一项本领，比如"查指标""做统计分析" |
| **工作空间** | 你所在团队的地盘。数据和看板按空间分开，互不干扰 |

## 二、【重点】第一次使用前，先确认这 3 件事

> **这一章是本手册最重要的部分。**
> 刚拿到账号的人，最常见的困惑就是"我登进来了，为什么问不出数？"——绝大多数情况就是下面三件事没到位。

### 先说结论

问数要能跑通，需要三样东西：

| # | 需要什么 | 通常谁来做 | 少了会怎样 |
|---|---------|-----------|-----------|
| **1** | 数据源已接入，且**你绑定了自己的查询账号** | **你自己做**（每个使用者都要做一次） | 提问后报错，查不出任何数 |
| **2** | 系统已配置好**大模型** | 管理员做 | 一直转圈，或报"没有可用的模型" |
| **3** | 有一个**可用的智能体** | 管理员做（系统自带几个） | 没有助理可选，发不出问题 |

第 1 条是**你要自己动手**的，也是最容易漏的，重点看 2.1。

---

### 2.1 条件一：绑定你自己的查询账号（★ 最容易卡住的一步）

#### 为什么必须绑定？

为了**数据权限隔离**。系统不会拿一个"超级账号"去查所有数，而是**用你本人的数据库账号**去查。这样一来：

- 你平时在数据库里看不到的数据，在这里也看不到；
- 不需要为了用这个工具额外申请一堆权限。

**代价**就是：每个使用者，对**每个自己要查的数据源**，都得绑定一次自己的账号。

> 如果你看到这句提示：
> **"当前用户未绑定数据源查询账号，请先在数据源页面配置查询账号后再执行查询"**
> —— 就是这个原因，照着下面做一遍即可。

#### 怎么做（4 步）

1. 顶部点 **配置** → 左侧选 **数据源**；
2. 在数据源列表里，**点击你要查的那个数据源**（选中后右侧出现详情）；
3. 在详情页工具栏上找到 **"绑定Aloudata账号"** 这个按钮，点开；
   > 💡 **别被名字误导**：按钮文字固定是"绑定Aloudata账号"，但**数据库数据源也点它**。
   > 弹窗里让你填的东西会根据数据源类型自动变化，数据库数据源就是填**你数据库的用户名和密码**。
4. 填完点 **测试连接**，显示"连接成功"后，再点 **保存**。

#### 填什么

| 数据源类型 | 弹窗让你填 | 填什么 |
|-----------|-----------|-------|
| MySQL / Oracle / PostgreSQL / ClickHouse 等数据库 | 查询用户名 + 查询密码 | **你自己的**数据库账号密码 |
| Aloudata 指标平台 | 认证值 | Aloudata 平台分配给你的认证值（auth-value） |

#### 几个提醒

- **一个数据源要绑一次**。你要查 3 个数据源，就绑 3 次；
- 绑定是**只读**的：系统只会用它执行查询，不会改你的数据；
- 任何时候都能在同一个弹窗里点 **删除绑定** 解除，或重新绑定别的账号；
- 换了数据库密码，记得回来**重新绑一次**，否则会连不上；
- **只有"成员"及以上角色才能绑定**。如果你的角色是**访客**，能看到数据源但不能绑定账号，也就**问不出数**——这种情况需要找管理员把你提升为"成员"。

---

### 2.2 条件二：系统已配置好大模型（管理员的事）

大模型是这个工具的"大脑"。**如果没配好，问数一定跑不通**——通常表现为一直转圈，或者直接报错。

你会看到这类提示：

- `无法构建 Agent：请先在「设置 → 模型」中配置并启用默认模型`
- `没有可用的模型配置`

**这不是你能解决的，找管理员**。管理员需要做的：接入大模型供应商（填入有效的 API Key），并确保至少有一个**已启用的**对话模型。详见 8.1。

---

### 2.3 条件三：有一个可用的智能体

"智能体"就是你对话的那个助理。你提问时，必须先选一个助理。

**你需要知道的是：**

- 系统**预置**了几个通用助理：**通用助手**、**任务规划师**、**推理分析师**，默认都是启用状态；
- 管理员通常还会为你建一个**专门为数据问数调优的助理**（可能叫"数据分析助手""数据分析师"或你们自己的命名）；
- **到底用哪个，入职时问一下管理员最省事**——一个问数准确的助理背后，是技能绑定、提示词、默认模型都调过的。

> ⚠️ **不要假设**助理一定叫"数据分析助手"。有的部署里并没有这个名字的助理，
> 遇到 `Agent 不存在` 或 `无权访问该 Agent`，多半是你用了别人环境里的示例名字。
> 正确做法是：在问数页面的**智能体下拉框**里，看实际有哪些可选，选管理员告诉你的那个。

在问数页面，右上角有 **切换智能体** 的下拉框，随时可以换。选好之后正常提问就行。

### 2.4 第一次登录自检清单

拿到账号后，按这个顺序走一遍，5 分钟内能确认自己能不能开工：

| 步骤 | 做什么 | 通过的标准 |
|-----|-------|-----------|
| 1 | 登录（见 3.1） | 进入问数页面，看到"欢迎使用问数智能体" |
| 2 | 确认右上角**工作空间**是不是你要用的那个 | 名字对得上（见 3.3） |
| 3 | 打开问数页右上角的**智能体下拉框** | 有可选助理，且是你该用的那个 |
| 4 | 去 **配置 → 数据源**，看看有没有数据源 | 至少有一个数据源 |
| 5 | 对你要查的数据源，**绑定你自己的查询账号**（见 2.1） | 点"测试连接"显示**连接成功** |
| 6 | 回到问数页，问一句最简单的 | 30 秒内出结论 + 图表 |

> 第 6 步如果报错，翻 **2.6 报错速查表**，基本一眼就能定位。

### 2.5 这几样不配也能用，但配了效果更好

下面这些**不是前置条件**，缺了不影响你问数，只是答案的"准"和"全"会打折扣。了解一下，知道该找谁就行。

| 项目 | 有什么用 | 不配的后果 | 谁来做 |
|------|---------|-----------|-------|
| **向量模型** | 让系统"按意思"找字段，而不是只按字面匹配 | 检索退化为关键词匹配，问法稍微换个说法就可能找不到 | 管理员 |
| **业务词典** | 教会系统你公司的叫法（比如"GMV"对应哪个字段） | **问不准的最常见原因**。你说"营收"，它可能找不到或找错 | 数据管理员 |
| **语义模型 + 逻辑关系** | 给字段起业务名、说明表之间怎么关联 | 多表查询容易关联错；跨表问题答不准 | 数据管理员 |
| **知识库** | 给助理喂业务背景文档（口径说明、FAQ） | 它不懂你们的业务约定，解释会比较"干" | 数据管理员 |
| **Python 运行环境** | 支撑统计检验、回归、聚类、预测这类高级分析 | 涉及这类分析的功能用不了（普通问数不受影响） | 管理员 |

> 实践建议：**先用起来，遇到"这个数查得不对"再回来针对性地补**。
> 补的顺序推荐：业务词典 → 语义模型 → 向量模型。详见第九章的排查顺序。

### 2.6 报错速查表（建议收藏）

看到提示别慌，对照下表：

| 你看到的提示 | 意思是 | 你该做什么 |
|-------------|-------|-----------|
| 当前用户未绑定数据源查询账号，请先在数据源页面配置查询账号后再执行查询 | 你还没绑定自己的数据库账号 | **自己绑**（见 2.1） |
| 当前用户未绑定 Aloudata 认证值… | Aloudata 数据源没填认证值 | **自己绑**（见 2.1） |
| 暂无可用数据源，请先在「配置」中添加 | 系统里一个数据源都没有 | 找管理员接入数据源 |
| 未找到您有权限访问的已启用数据源，请先在数据源页面配置或授权后再检索 | 数据源没启用，或没授权给你 | 先绑认证值，仍不行找管理员 |
| 无法构建 Agent：请先在「设置 → 模型」中配置并启用默认模型 | 大模型没配好 | 找管理员（见 2.2） |
| 没有可用的模型配置 | 同上 | 找管理员 |
| Agent 不存在 / 无权访问该 Agent | 助理被删了，或没给你权限 | 换个助理，或找管理员 |
| 指标不存在…请勿使用中文展示名 | 指标还没同步到本地 | 找管理员做 Aloudata 同步（见 8.2） |
| 该账号未开通本地登录，请使用「开机账号登录」或「UM 账号登录」 | 你选错了登录方式 | 换对应的登录标签页（见 3.1） |
| 登录失败次数过多，请稍后再试 | 输错太多次被临时锁定 | 等 5 分钟再试（见 3.2） |
| 没有权限 / 403 | 你的角色不够做这件事 | 找管理员（见 3.3） |
| 当前工作区下没有可用的 Agent | 这个空间里没有启用的助理 | 切换工作空间，或找管理员 |

## 三、登录与工作空间

### 3.1 怎么登录

系统支持三种登录方式，**具体能用哪种取决于你们公司的部署**。登录页顶部的标签页就是所有可用方式：

| 登录方式 | 用哪个账号 | 说明 |
|---------|-----------|------|
| **开机账号登录** | 公司电脑的开机账号 | 企业统一认证 |
| **UM 账号登录** | 你的 UM / OA 账号 | 企业统一认证 |
| **本地账号登录** | 管理员单独给你的账号密码 | 独立账号，与公司账号无关 |

**几种常见情况：**

- **只看到"账号 / 密码"两个输入框，没有标签页** → 说明你们用的是本地账号模式，直接输管理员给的用户名密码即可；
- **打开页面就自动进去了** → 说明你在公司内网已经登录过办公系统，系统做了**单点登录（SSO）**，不用再输密码；
- **平时用开机账号，但提示"该账号未开通本地登录"** → 你选到了"本地账号登录"标签，切回"开机账号登录"就行；
- **突然出现图形验证码** → 是因为连续输错触发了风控，照图输入即可。

首次登录的账号密码由管理员分配。

### 3.2 关于账号的几件事

**关于密码修改：**

> ⚠️ **当前版本的用户界面里没有"修改密码"入口**（右上角头像下拉只有"退出登录"）。
> 需要改密码，**请联系管理员帮你重置**。这一点和很多系统的习惯不一样，不要再找"个人设置"里改密码的入口了。

**关于登录失败被锁：**

同一个账号 **5 分钟内连续输错 10 次**，会被临时锁定，提示"登录失败次数过多，请稍后再试"。稍等几分钟再试，或找管理员。

**关于登录有效期：**

登录状态有效期 24 小时。正常使用过程中系统会自动续期，一般不会让你反复登录。

### 3.3 工作空间

**工作空间**是你和你的团队各自独立的"地盘"。**数据、数据源、看板、报告都是按工作空间隔离的**——在 A 空间看不到 B 空间的东西。

- 右上角点**工作空间下拉框**切换；
- 系统默认会给你一个可用的工作空间（通常叫 `Default`），所以不会出现"登录进来什么都没有"的情况；
- 切换后"什么都看不到"是**正常现象**，数据本来就分开的，切回来就行，账号本身没变。

你在每个空间里的**角色**，决定了你能做什么：

| 角色 | 你能做什么 |
|------|-----------|
| **所有者** | 全部权限 |
| **管理员** | 管理成员、接数据、配系统 |
| **成员** | 用数据、做看板、发报告；**能绑定自己的查询账号** ← **业务用户通常就是这个** |
| **访客** | 只能看和基本使用。**不能绑定查询账号，因此无法实际问数** |

> 看到"没有权限"，说明这项操作需要更高角色，找管理员即可。
> 另外注意：在**配置**里，只有"管理员/所有者"能改动数据源、业务词典、智能体等配置；"成员"可以进去**查看**并**绑定自己的查询账号**——这也是成员唯一需要在配置页做的操作。

### 3.4 退出登录

右上角点**你的头像** → **退出登录**。

## 四、智能问数（怎么提问）

入口：顶部 **问数**。这是你每天用得最多的页面。

页面打开后，屏幕中间会有一句问候（"上午好，请问有什么可以帮您？"），下面有**几个快捷入口**（比如"近 30 天 AUM 变化趋势""各渠道 GMV 占比"），点一下就能直接问——**不知道怎么开口的时候，先从这些快捷入口点**，看完它的回答你就明白该怎么提问了。

### 4.1 怎么问才问得准

一句话说清**三件事**，命中率最高：

1. **要什么数**（指标）：销售额？利润？订单量？用户数？
2. **什么时间**：这个月、上周、2025 年一季度、近 30 天；
3. **按什么拆**（维度）：按地区、按产品、按渠道。

三件事里**时间**最容易漏，也最容易导致答案不合预期，建议养成"带时间"的习惯。

### 4.2 提问示例

| 你想干什么 | 照着这么说 |
|-----------|-----------|
| 要一个数 | "上个月总销售额是多少？" |
| 做对比 | "各产品线本季度销售额对比" |
| 看走势 | "近一年每月用户数变化趋势" |
| 看涨跌 | "本月销售额环比增长多少？" |
| 看排名 | "销量最高的 Top 5 商品" |
| 看占比 | "各渠道销售额占比" |

### 4.3 回答过程中你会看到什么

简单问题一般 **30 秒内**出结果。等待过程中屏幕上会依次出现几段内容，**这是正常现象，不是卡住**：

| 屏幕上出现的 | 是什么意思 |
|-------------|-----------|
| **思考过程** | 它在琢磨你这句话该怎么理解 |
| **查询计划 / 执行过程 / 工具执行** | 它在实际去数据库取数了，你能看到它查了什么 |
| **正文 + 图表** | 最终答案：先一段话讲结论，再配一张图 |

图表类型是它**自动选**的：时间走势用折线，分类对比用柱状，占比用饼图——不用你指定。

> 如果它跑偏了，**随时可以点"停止"**。

### 4.4 多轮追问，不用重复条件

同一个对话里，顺着上一条继续问就行，它记得上文：

- "那 3 月呢？"（只换时间）
- "环比呢？"（只换算法）
- "按区域拆开看看。"（只换维度）

### 4.5 它反问你的时候，是好事

如果同一个词在数据库里有两种口径（比如"营收"有两种算法），它会**列出几个选项让你确认**。

**这是刻意设计，为了答得准，不是报错。** 照着点一下就好。它宁可多问一句，也不愿意给你一个错的数。

### 4.6 其它好用的小功能

| 功能 | 在哪儿 | 怎么用 |
|------|-------|-------|
| **指定数据源** | 提问框附近 | 默认"不限制"，也可以限定只查某几个数据源 |
| **切换智能体** | 页面右上角 | 换不同的助理来回答 |
| **上传附件** | 提问框 | 可以把截图、报表文件一起丢进来问 |
| **优化输入** | 提问框 | 把你的话润色成更规范的问题再发出去 |
| **停止 / 重新生成** | 回答上方 | 答得不好可以重来 |
| **新对话 / 清空对话** | 左上角 | 换一个话题建议开新对话，避免上文干扰 |
| **推荐追问** | 回答下方 | 每次答完会给你几个"接下来可以问什么"的快捷按钮 |
| **看口径** | 图表上 | 点开"指标查看"，能看到这张图用的指标、时间、筛选条件 |
| **历史会话** | 左侧列表 | 可重命名、置顶、删除 |

## 五、洞察仪表盘（把数做成看板）

入口：顶部 **洞察**。

看板有两种做法：**让 AI 帮你做**（省事），或者**自己拖拽搭**（灵活）。生成好的看板也可以继续让 AI 改。

### 5.1 方式一：一句话让 AI 生成（推荐）

1. 进入看板布局页，找到 AI 输入框；
2. 一句话描述你要什么，例如：
   > "帮我建一个华东区销售看板，包含销售额、订单量、各产品占比"
3. 回车，AI 自动生成看板并保存；
4. 想改，继续对它说就行，比如"把销售额改成折线图""加一个时间筛选器"。

### 5.2 方式二：自己拖拽搭建

进入编辑器后，左侧是**组件库**，往画布里拖：

| 组件 | 用来做什么 |
|------|-----------|
| **KPI 卡片** | 摆一个核心数字（如"本月销售额"） |
| **图表** | 折线 / 柱状 / 饼图 |
| **表格** | 看明细数据 |
| **筛选器** | 给看板加个下拉，切换不同维度 |
| **时间筛选** | 今天 / 近 7 天 / 30 天 / 90 天 / 自定义 |

**几个要点：**

- 每个组件（图表 / 卡片 / 表格）都要**绑定数据**——也就是选它用哪个指标。绑定后可以直接在旁边**预览取数结果**，不用来回切换；
- **全局筛选器**影响整个看板；单个图表也可以挂自己的筛选器；
- **某个组件取数失败不会拖垮整个看板**，它会单独提示，其余组件照常显示。

### 5.3 看看板

在"洞察"列表点开某个看板，进入**预览页**，可以按筛选器实时看数。

### 5.4 AI 报告 + 归因分析

看板里可以触发 **AI 报告**：系统自动把看板上的数字填进报告，AI 负责写"趋势、关键发现、建议"，并自动做**归因分析**回答"为什么这块数据变了"。

## 八、管理员配置与维护（业务用户可跳过）

> **给管理员看的章节。**
> 建议按下面的顺序配置：**先配模型（否则谁都问不了数）→ 接入数据源 → 教系统认识业务词 → 配置智能体**。
> 业务用户不需要读这一章，但**2.1 里"绑定查询账号"这步是每个使用者自己要做的**，可以把这个动作告诉他们。

配置入口：顶部 **配置**。左侧按三组排列：

- **能力**：技能、智能体
- **数据**：数据源、业务词典、知识库
- **平台**：模型、工作空间

### 8.1 模型配置（必须最先做）

大模型是"问数的大脑"，**不配好，所有人都无法问数**。用户侧的表现是"一直转圈"或"无法构建 Agent：请先在「设置 → 模型」中配置并启用默认模型"。

| 配置项 | 说明 |
|-------|------|
| **管理 Provider** | 接入大模型供应商（通义 / OpenAI / Anthropic / DeepSeek 等），填入 **API Key** 并测试连接 |
| **添加模型** | 在供应商下登记用哪个模型 |
| **模型发现** | 一键拉取该供应商可用的模型列表 |
| **默认模型** | 全局默认用它回答 |
| **激活模型** | 临时优先使用的模型（优先于默认） |
| **向量模型** | 负责"语义理解"的另一类模型。**配了检索更准**（不配会自动退化成关键词匹配，仍可用）；不配时后端会打日志"没有可用的 embedding 模型配置…" |

> **判断标准**：至少要有一个**已启用**的对话模型，且它所属的 Provider **填了有效的 API Key**。只登记模型、不填 Key 是跑不起来的。
> 底座支持**多供应商故障转移**：当前供应商挂了会自动切下一个，不容易"一问就挂"。

### 8.2 数据源管理（把数据接进来）

#### 新建数据源：3 步

1. **选来源**：数据库类型（MySQL、PostgreSQL、Oracle、ClickHouse、Doris 等十多种），或 **Aloudata 指标平台**；
2. **填连接**：地址、账号密码，系统**自动测试连通性**；可绑定一个"查询账号"作为系统后续查询用；
3. **完成**：保存后系统自动扫描出**表、字段、主键、索引**（Schema 发现）。

#### 日常管理

| 操作 | 说明 |
|------|------|
| 编辑 / 删除 | 改连接信息（会重新测连通）或删除 |
| 启用 / 停用 | **停用后问数就不会用到它**。用户看不到未启用的数据源 |
| 预览数据 | 查看某张表前 100 行 |
| Aloudata 同步 | 把指标平台的**指标 / 维度 / 类目**同步到本地（**问指标类问题的前提**，见下） |
| 同步过滤规则 | 对接 Aloudata 时可选，按规则过滤掉不要的指标 / 维度 |

#### ⚠️ 关键：每个使用者必须自己绑定查询账号

系统**不允许**回退到数据源的管理员账号。也就是说，**对于关系型数据库数据源，如果使用者没有绑定自己的查询账号，他的每一次查询都会失败**，报错：

> `当前用户未绑定数据源查询账号，请先在数据源页面配置查询账号后再执行查询`

对应代码逻辑是硬性的（`DatasourceQueryTool`：查询账号为空或未启用即直接返回错误，无回退分支）。

- 绑定入口：**配置 → 数据源 → 选中数据源 → 工具栏 "绑定Aloudata账号" 按钮**；
- 关系型数据库弹窗里填**用户自己的**数据库用户名 / 密码；Aloudata 数据源填**认证值（auth-value）**；
- 绑定时可先点"测试连接"验证；
- **这是使用者自助操作**（接口按当前登录用户维度存绑定关系），管理员无法代绑，所以务必在开通账号时把这一步交代清楚。

#### Aloudata 指标平台的两个附加条件

1. **必须做一次元数据同步**。指标 / 维度是同步到**本地**再检索的，`aloudata_search_semantic` 查的是本地语义层。**从未同步过，指标类问题就问不准**，可能报 `指标不存在。请先调用 aloudata_search_semantic 确认指标的英文名(metricName)`；
   - 同步状态判断：指标数为 0 即"未同步"；
   - 同步后如检索仍不准，可再执行 **重建 ES 索引**。
2. **使用者必须绑定自己的 Aloudata 认证值**，否则报 `当前用户未绑定 Aloudata 认证值…`。

> 注意：指标和维度**常常共用同一批名字**。用"同步过滤规则"只想过滤某一侧时，规则里要写清类型（`categoryType`），否则容易连带过滤掉另一侧。

#### 让问数更准的两项配置（问不准时再来配）

| 配置 | 是干什么的 | 什么时候配 |
|------|-----------|-----------|
| **语义模型** | 给每个字段起业务名、写清含义（如字段 `amount` ← 业务名"金额"，备注"含税"），系统就能听懂你说的"金额" | 用户反馈"问的字段对不上"时，建一套最有效 |
| **逻辑关系** | 手工声明两张表怎么关联（如订单表 ↔ 客户表 = 多个订单属于一个客户） | 数据库没写外键、多表查询总关联错时 |

> 两者都支持**从已有表结构"自动初始化"生成一份初稿**，再人工微调，比从零建省事得多。

### 8.3 业务词典（教系统认识"你公司的黑话"）

把"用户嘴里的词"映射到"库里的字段"。**这是问数准不准的重中之重**，也是最容易见效的一项。

例子：用户总说"**GMV**"，而数据里字段叫 `gross_merchandise_value`，就配一条"GMV → 该字段，同义词：成交额、销售额"。

| 操作 | 说明 |
|------|------|
| 新增术语 | 标准名 + 对应字段 + 同义词 + 口径说明 |
| 启用 / 停用 | 是否参与检索 |
| 语义检索 / 重建 | **改完词典后必须点"重建索引"，新词才会生效** |

> 业务词典缺失**不会报错**，只会导致答不准——所以它容易被忽略，但排查"问不准"时它是第一顺位。

### 8.4 知识库

放业务知识文档（产品说明、口径定义、FAQ），可绑定到智能体，让它在回答时参考。支持**文本导入**和**文件导入**。

### 8.5 技能管理

技能 = 一份可复用的"操作说明书"。系统启动时会自动扫描安装内置技能（`skill_type=builtin`，默认**启用**），DataAgent 模块自带三个：

| 技能 | 用途 |
|------|------|
| **指标查询**（aloudata_metric_query） | 教助理怎么一步步问指标 |
| **指标归因分析**（aloudata_metric_attribution_analysis） | 解释指标为什么变化 |
| **Python 分析**（python_analysis） | 统计检验、回归、聚类、预测等高级分析 |

可用的操作：创建、启停、**安全扫描**、从**技能市场**安装、**上传 ZIP 包**安装、卸载。

> **技能绑定规则**：智能体如果**没有**单独配置技能绑定，会**自动继承全部已启用技能**。所以新建的智能体天然就有上述本领，除非你显式关闭。

### 8.6 智能体（配置"助理"本身）

智能体就是用户对话的那个"助理"。

| 配置 | 说明 |
|------|------|
| 名称 / 描述 / 提示词 | 定义助理的"人设"和回答规则 |
| 绑定技能 | 给它开哪些本领；**不配则继承全部已启用技能** |
| 绑定知识库 | 让它回答时参考哪些知识 |
| 偏好模型 | 指定它优先用哪个大模型 |
| 上下文文件 | 给助理"定性格 / 记事情"的 Markdown 文件（如 PROFILE、MEMORY），可设置先后顺序 |
| 启用 / 停用 | **停用后用户在对话列表里就选不到它了** |

> ⚠️ **重要提醒：系统预置的并不是"数据分析助手"。**
> 数据库初始化脚本预置的是三个**通用**智能体：**通用助手**、**任务规划师**、**推理分析师**，它们没有针对数据问数做过提示词和技能调优。
> 「数据分析助手」这个名字出现在**技能模板**（skill-templates/data-analyst-prompt）和**智能体模板**（templates/data-analyst.json，实际名称为「数据分析师」）里，需要**手动从模板创建**，并非开箱即用。
>
> **建议管理员为业务用户专门创建一个问数智能体**（从"数据分析师"模板创建，或自行编写提示词），并在交付账号时明确告诉用户"用哪个助理"。这直接决定用户的第一次体验。

### 8.7 工作空间（账号与权限）

#### 成员管理

| 操作 | 说明 |
|------|------|
| 添加成员 | 把用户加进当前空间。新用户需要填**初始密码**（"新用户必填，已有用户忽略"） |
| 设角色 | 所有者 > 管理员 > 成员 > 访客 |
| 移除成员 | 移除后无法访问本空间 |

> ⚠️ **企业认证模式下的注意点**：当部署开启了企业统一认证（AD/UM）时，**本地登录通道只对白名单账号开放（默认仅 `admin`）**。也就是说，通过"添加成员"邀请的普通用户，如果不在白名单里，是**无法用本地账号密码登录的**，必须走 AD / UM 登录。

#### 资源授权

对"技能 / 智能体 / 数据源 / 业务词典 / 知识库"等资源，可以**单独授权给某个人或某个角色**：

- 权限分三级：**查看 < 使用 < 编辑**；
- 可设**过期时间**，可**撤销**。

#### 审批流

"发布技能 / 发布智能体 / 关键授权"等敏感操作可走审批：**待审批 → 通过 / 拒绝 / 撤回**。成员提交，管理员审批。

#### 定时任务

可创建按计划执行的定时任务（如定时同步数据源），支持启用 / 停用 / 手动立即执行。

### 8.8 代码执行器（Python 分析的前提）

Python 相关分析（统计检验、回归、聚类、预测）依赖本机的 Python 运行时：

- 开关：`mateclaw.code-executor.enabled`（默认开启）；
- 系统会自动在 PATH 中探测 `python3` / `python` 与 `pip`；
- 探测不到时日志会提示 `未检测到可用的 Python 解释器，Python 分析功能将不可用`，用户侧报 `Python 执行环境不可用，请确保系统已安装 Python`；
- **影响范围仅限 Python 分析类功能，普通问数不受影响。**

### 8.9 帮助中心内容维护

帮助中心的表结构、CRUD 接口都已就绪（`/v1/help-center/...`），但**仓库里没有任何初始化文档数据**，因此全新部署的帮助中心是空的（"暂无分类""该分类下暂无文档"）。分类和文档需要管理员手工录入（创建分类为全局管理员权限）。

## 九、常见问题

**问数结果不准 / 找不到某个数？**

按这个顺序排查，绝大多数是第 1 条：

1. **业务词典**里有没有用户这个叫法？（没有就加一条，**改完记得点"重建索引"**）
2. **语义模型**里，核心字段是否写清了业务名和含义？
3. 多表场景，**逻辑关系**配了没？
4. 是不是**向量模型**没配，导致检索退化成了关键字匹配？

**问不了数据（一直转圈 / 报没有可用模型）？**

多半是大模型没配好。找管理员确认：Provider 是否已接入且**填了有效 API Key**、是否设置了默认 / 激活模型。**注意：只登记模型不填 Key 是无效配置。**

**提示"当前用户未绑定数据源查询账号"？**

这是使用者**必须自己完成**的一步。见 2.1，绑定后立即生效。

**某些分析（统计 / 聚类 / 预测）用不了？**

依赖本机 Python 运行时。找管理员确认安装了 Python 且配置在 PATH 中，且 `代码执行器` 已开启。普通问数不受影响。

**提示"没有权限 / 403"？**

依次确认：① 当前**工作空间**对不对；② 你的**角色**够不够；③ 这份报表 / 数据源是否属于当前空间且对你开放。都不行就找管理员。

**登录被锁 / 突然要验证码？**

同账号 5 分钟内输错 10 次会被临时锁定，等几分钟或找管理员。企业认证触发风控时会要求图形验证码。

**想改密码，但找不到入口？**

当前版本**用户界面没有改密码入口**，请联系管理员重置。

**回答中途断了 / 想要重新回答？**

点"停止"可以中断生成。历史对话是保存的，刷新页面后仍在；觉得答案不好，可以点**"重新生成"**让它重跑一次，或补一句话追问把方向纠正过来。

**Aloudata 同步后指标变少了？**

可能被"同步过滤规则"过滤掉了。注意指标和维度常共用一类名字，只想过滤某一侧时规则里要写清类型（`categoryType`）。

**切换工作空间后啥都没有了？**

正常现象。数据、看板都是按工作空间隔离的，切回来即可，账号本身没变。

## 十、给开发者的接入说明（API / SDK）

> 本章面向开发 / 集成人员，业务用户可以跳过。

### 10.1 接口文档

Swagger 地址：`http://<host>:18089/dataagent/api/v1/swagger-ui.html`

### 10.2 认证

- 登录获取 **JWT**（有效期 24 小时），放请求头 `Authorization: Bearer xxx`；
- 无头脚本可使用 **PAT**（个人访问令牌）；
- 每个请求需带 **`X-Workspace-Id`** 头指明当前工作空间；不传时后端回退到默认工作空间（id=1）。

### 10.3 Python 客户端

安装（本地）：

```bash
cd mateclaw-dataagent-client-python
pip install -e .
```

跑通一个例子（登录 → 对话）：

```python
from mateclaw_dataagent import DataAgentClient

client = DataAgentClient(base_url="http://localhost:18089/dataagent/api", workspace_id=1)
client.login(username="admin", password="admin123")

resp = client.chat(agent_id=1, message="本月销售额是多少", conversation_id="demo-1")
print(resp.content)

client.close()
```

流式对话（可以实时看到"思考 / 工具 / 正文"分段的 SSE 事件）：

```python
for event in client.stream_chat(agent_id=1, message="上月销售额", conversation_id="demo-2"):
    if event.event == "content_delta":
        print(event.delta, end="", flush=True)
    elif event.event == "done":
        print("\n完成")
```

> ⚠️ 示例里的 `agent_id=1` 只是占位。请先用**实际的智能体 ID**替换，并确认该智能体已启用、且当前用户对它有权访问，否则会报 `Agent 不存在` / `无权访问该 Agent`。
> 另外，示例中 `AGENT_NAME = "数据分析助手"` 也是示例值——**系统初始化并不会创建这个名称的智能体**（详见 8.6），直接运行示例前请先确认环境里存在该智能体。

更多用法（会话管理、大模型直连、AI 测评框架）见 `mateclaw-dataagent-client-python/README_CN.md` 及 `examples/`。

### 10.4 WebChat 网页内嵌

要把问数聊天嵌入你们自己的网站：引入 `mateclaw-webchat.umd.js`，调用 `MateClawWebChat.init(...)` 即可，详见 `mateclaw-webchat` 模块说明。
